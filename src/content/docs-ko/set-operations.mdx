# 집합 연산

SQL 집합 연산은 여러 query block의 결과를 하나의 결과로 결합합니다. 
SQL 표준은 다음 집합 연산을 정의합니다: `UNION`, `INTERSECT`, `EXCEPT`, `UNION ALL`, `INTERSECT ALL`, `EXCEPT ALL`.

### Union
두 query block의 모든 결과를 하나로 합치되, 중복은 제거합니다.

customers와 users 테이블의 모든 이름을 중복 없이 가져옵니다.

### Union All
두 query block의 모든 결과를 하나로 합치며, 중복도 유지합니다.

한 테이블은 온라인 판매를, 다른 테이블은 오프라인 매장 판매를 나타낸다고 가정해 보겠습니다.
이 경우 두 테이블의 데이터를 하나의 결과 집합으로 결합하고 싶습니다. 중복 거래가 있을 수 있으므로,
중복을 제거하지 않고 모든 record를 유지하고자 합니다.

### Intersect
두 query block의 결과에 공통으로 존재하는 row만 결합하며, 중복은 제거합니다.

학생의 수강 신청 정보를 저장한 두 테이블이 있다고 가정해 보겠습니다.
두 다른 학과에 공통으로 존재하는 강의를 찾고 싶지만,
강의 이름은 중복 없이 얻고 싶고, 같은 학생이 같은 강의를 여러 번 수강한 경우를
따로 세고 싶지는 않습니다.

이 시나리오에서는 두 학과 사이에 공통으로 존재하는 강의를 찾고 싶지만,
같은 학과의 여러 학생이 수강하고 있더라도 같은 강의를 여러 번 세고 싶지는 않습니다.

### Intersect All
두 query block의 결과에 공통으로 존재하는 row만 결합하되, 중복은 유지합니다.

고객 주문 데이터를 담은 두 테이블이 있고,
일반 고객과 VIP 고객 모두가 주문한 상품을 찾고 싶다고 가정해 보겠습니다.
이 경우 서로 다른 고객이 같은 상품을 여러 번 주문했더라도,
각 상품의 수량 정보를 유지하고 싶습니다.

이 시나리오에서는 일반 고객과 VIP 고객 모두가 주문한 상품을 찾되,
같은 상품이 서로 다른 고객에 의해 여러 번 주문되더라도 수량 정보를 유지하고자 합니다.

### Except
두 query block A와 B에 대해, B에는 없고 A에만 있는 모든 결과를 반환하며 중복은 제거합니다.

직원의 프로젝트 배정 정보를 저장한 두 테이블이 있다고 가정해 보겠습니다.
한 부서에만 속하고 다른 부서와는 공유되지 않는 프로젝트를
중복 없이 찾고 싶습니다.

이 시나리오에서는 한 부서에만 속하고 다른 부서와 공유되지 않는 프로젝트를 식별하고 싶습니다.
같은 부서의 여러 직원이 같은 프로젝트에 배정되어 있더라도,
같은 프로젝트를 여러 번 세고 싶지는 않습니다.

### Except All
두 query block A와 B에 대해, B에는 없고 A에만 있는 모든 결과를 반환하되 중복은 유지합니다.

고객 주문 데이터를 담은 두 테이블이 있고,
VIP 고객 없이 일반 고객만 주문한 상품을 식별하고 싶다고 가정해 보겠습니다.
이 경우 같은 상품이 서로 다른 일반 고객에 의해 여러 번 주문되더라도,
각 상품의 수량 정보를 유지하고 싶습니다.

이 시나리오에서는 일반 고객만 주문하고 VIP 고객은 주문하지 않은 상품을 찾고 싶습니다.
같은 상품이 서로 다른 일반 고객에 의해 여러 번 주문되더라도 수량 정보를 유지하고자 합니다.
