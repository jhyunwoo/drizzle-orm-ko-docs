# SQL Insert
Drizzle ORM은 데이터베이스 테이블에 row를 insert하는 가장 SQL-like한 방법을 제공합니다.

Drizzle로 데이터를 insert하는 일은 매우 직관적이고 sql-like합니다. 직접 확인해 보세요:

<Section>
```typescript copy 
await db.insert(users).values({ name: 'Andrew' });
```
```sql
insert into "users" ("name") values ("Andrew");
```
</Section>

특정 테이블의 insert type이 필요하다면 `typeof usersTable.$inferInsert` 문법을 사용할 수 있습니다. 
```typescript copy 
type NewUser = typeof users.$inferInsert;

const insertUser = async (user: NewUser) => {
  return db.insert(users).values(user);
}

const newUser: NewUser = { name: "Alef" };
await insertUser(newUser);
```

## returning
<IsSupportedChipGroup chips={{ 'PostgreSQL': true, 'SQLite': true, 'MySQL': false, 'SingleStore': false, 'MSSQL': false, 'CockroachDB': true }} />
PostgreSQL과 SQLite에서는 다음과 같이 row를 insert하고 그 값을 다시 받을 수 있습니다:
```typescript copy
await db.insert(users).values({ name: "Dan" }).returning();

// partial return
await db.insert(users).values({ name: "Partial Dan" }).returning({ insertedId: users.id });
```

## $returningId
<IsSupportedChipGroup chips={{ 'PostgreSQL': false, 'SQLite': false, 'MySQL': true, 'SingleStore': true, 'MSSQL': false, 'CockroachDB': false }} />

MySQL 자체는 `INSERT` 이후 `RETURNING`을 기본으로 지원하지 않습니다. `autoincrement`(또는 `serial`) 타입의 `primary keys`에 대해서만 한 가지 방법이 있는데, 이 경우 `insertId`와 `affectedRows` field에 접근할 수 있습니다. Drizzle에서는 이런 경우를 처리하고 insert된 모든 ID를 별도의 object로 자동으로 받을 수 있도록 준비해 두었습니다.

```ts
import { boolean, int, text, mysqlTable } from 'drizzle-orm/mysql-core';

const usersTable = mysqlTable('users', {
  id: int('id').primaryKey(),
  name: text('name').notNull(),
  verified: boolean('verified').notNull().default(false),
});


const result = await db.insert(usersTable).values([{ name: 'John' }, { name: 'John1' }]).$returningId();
//    ^? { id: number }[]
```

또한 Drizzle에서는 런타임에 사용자 정의 primary key를 생성하는 `$default` 함수와 함께 `primary key`를 지정할 수 있습니다. 이 경우에도 `$returningId()` 호출에서 생성된 key를 반환해 드립니다.

```ts
import { varchar, text, mysqlTable } from 'drizzle-orm/mysql-core';
import { createId } from '@paralleldrive/cuid2';

const usersTableDefFn = mysqlTable('users_default_fn', {
  customId: varchar('id', { length: 256 }).primaryKey().$defaultFn(createId),
  name: text('name').notNull(),
});


const result = await db.insert(usersTableDefFn).values([{ name: 'John' }, { name: 'John1' }]).$returningId();
//  ^? { customId: string }[]
```

> primary key가 없다면 -> 이런 query의 타입은 `{}[]`가 됩니다


## Upserts and conflicts
Drizzle ORM은 upsert와 conflict를 처리하기 위한 간단한 interface를 제공합니다.

### On conflict do nothing
<IsSupportedChipGroup chips={{ 'PostgreSQL': true, 'SQLite': true, 'MySQL': false, 'SingleStore': false, 'CockroachDB': true }} />

`onConflictDoNothing`은 conflict가 있으면 insert를 취소합니다:

```typescript copy
await db.insert(users)
  .values({ id: 1, name: 'John' })
  .onConflictDoNothing();

// explicitly specify conflict target
await db.insert(users)
  .values({ id: 1, name: 'John' })
  .onConflictDoNothing({ target: users.id });
```

### On conflict do update

<IsSupportedChipGroup chips={{ 'PostgreSQL': true, 'SQLite': true, 'MySQL': false }} />

`onConflictDoUpdate`는 conflict가 있으면 row를 update합니다:
```typescript
await db.insert(users)
  .values({ id: 1, name: 'Dan' })
  .onConflictDoUpdate({ target: users.id, set: { name: 'John' } });
```

#### `where` clauses

`on conflict do update`에는 두 군데에 `where` clause를 둘 수 있습니다.
하나는 conflict target의 일부(즉 partial index용)이고, 다른 하나는 `update` clause의 일부입니다:

```sql
insert into employees (employee_id, name)
values (123, 'John Doe')
on conflict (employee_id) where name <> 'John Doe'
do update set name = excluded.name

insert into employees (employee_id, name)
values (123, 'John Doe')
on conflict (employee_id) do update set name = excluded.name
where name <> 'John Doe';
```

Drizzle에서 이 조건들을 지정하려면 `setWhere`와 `targetWhere` clause를 사용할 수 있습니다:

```typescript
await db.insert(employees)
  .values({ employeeId: 123, name: 'John Doe' })
  .onConflictDoUpdate({
    target: employees.employeeId,
    targetWhere: sql`name <> 'John Doe'`,
    set: { name: sql`excluded.name` }
  });

await db.insert(employees)
  .values({ employeeId: 123, name: 'John Doe' })
  .onConflictDoUpdate({
    target: employees.employeeId,
    set: { name: 'John Doe' },
    setWhere: sql`name <> 'John Doe'`
  });
```

<hr />

복합 index 또는 복합 primary key를 사용하는 `onConflictDoUpdate` upsert:

```typescript
await db.insert(users)
  .values({ firstName: 'John', lastName: 'Doe' })
  .onConflictDoUpdate({
    target: [users.firstName, users.lastName],
    set: { firstName: 'John1' }
  });
```

### On duplicate key update
<IsSupportedChipGroup chips={{ 'PostgreSQL': false, 'SQLite': false, 'MySQL': true, 'SingleStore': true, 'CockroachDB': false }} />

MySQL은 `ON CONFLICT` clause 대신 [`ON DUPLICATE KEY UPDATE`](https://dev.mysql.com/doc/refman/8.0/en/insert-on-duplicate.html)를 지원합니다. MySQL은 primary key와 unique index를 기반으로 conflict target을 자동으로 결정하고, *어떤* unique index에서든 conflict가 발생하면 row를 update합니다.

Drizzle은 `onDuplicateKeyUpdate` method를 통해 이를 지원합니다:

```typescript
// Note that MySQL automatically determines targets based on the primary key and unique indexes
await db.insert(users)
  .values({ id: 1, name: 'John' })
  .onDuplicateKeyUpdate({ set: { name: 'John' } });
```

MySQL은 conflict 시 아무 작업도 하지 않는 기능을 직접 지원하지는 않지만, 아무 column이나 자기 자신으로 값을 설정하면 no-op를 수행하여 같은 효과를 낼 수 있습니다:

```typescript
import { sql } from 'drizzle-orm';

await db.insert(users)
  .values({ id: 1, name: 'John' })
  .onDuplicateKeyUpdate({ set: { id: sql`id` } });
```

## `with insert` clause

<Callout>
  [select](/docs/select#with-clause), [update](/docs/update#with-update-clause), [delete](/docs/delete#with-delete-clause)에서 WITH statement를 사용하는 방법을 확인하세요
</Callout>

`with` clause를 사용하면 common table expression (CTE)라고 불리는 더 작은 subquery로 나누어 복잡한 query를 단순화하는 데 도움이 됩니다:
<Section>
```typescript copy
const userCount = db.$with('user_count').as(
	db.select({ value: sql`count(*)`.as('value') }).from(users)
);

const result = await db.with(userCount)
	.insert(users)
	.values([
		{ username: 'user1', admin: sql`((select * from ${userCount}) = 0)` }
	])
	.returning({
		admin: users.admin
	});
```
```sql
with "user_count" as (select count(*) as "value" from "users") 
insert into "users" ("username", "admin") 
values ($1, ((select * from "user_count") = 0)) 
returning "admin"
```
</Section>


## Insert into ... select

SQLite 문서에서 언급하듯이:

<Callout>
INSERT statement의 두 번째 형태는 VALUES clause 대신 SELECT statement를 포함합니다. 
SELECT statement를 실행해 반환된 데이터의 각 row마다 테이블에 새 항목이 insert됩니다. 
column-list가 지정된 경우에는 SELECT 결과의 column 수가 
column-list 항목 수와 같아야 합니다. 반대로 column-list가 지정되지 않았다면, SELECT 결과의 
column 수는 테이블의 column 수와 같아야 합니다. 
compound SELECT와 ORDER BY 및/또는 LIMIT clause가 포함된 SELECT statement를 포함해, 
어떤 SELECT statement든 이 형태의 INSERT statement에 사용할 수 있습니다.
</Callout>
<Callout type='warning'>
파싱 모호성을 피하려면 upsert-clause가 있을 때 SELECT statement에는 항상 WHERE clause가 포함되어야 합니다. 그 clause가 단순히 "WHERE true"이더라도 마찬가지입니다. WHERE clause가 없으면 parser는 "ON" 토큰이 SELECT의 join constraint 일부인지, 아니면 upsert-clause의 시작인지 알 수 없습니다.
</Callout>

PostgreSQL 문서에서 언급하듯이:
<Callout>
insert될 row를 제공하는 query(SELECT statement)
</Callout>

그리고 MySQL 문서에서 언급하듯이:

<Callout>
INSERT ... SELECT를 사용하면 하나 또는 여러 테이블에서 선택할 수 있는 SELECT statement의 결과를 바탕으로 많은 row를 테이블에 빠르게 insert할 수 있습니다
</Callout>

Drizzle은 현재 문법을 모든 dialect에서 지원하며, 모두 같은 문법을 공유합니다. 몇 가지 일반적인 시나리오와 API 사용법을 살펴보겠습니다. 
insert statement 안에서 select를 사용하는 방법은 여러 가지가 있으므로, 선호하는 접근 방식을 고를 수 있습니다:

- select 함수 안에 query builder를 전달할 수 있습니다.
- callback 안에서 query builder를 사용할 수 있습니다.
- 원하는 어떤 사용자 정의 select query든 사용할 수 있는 SQL template tag를 전달할 수 있습니다.
