Limit은 반환할 행 수 `(page size)`이고, offset은 건너뛸 행 수 `((page number - 1) * page size)`입니다. 
일관된 페이지네이션을 위해서는 고유한 열로 정렬해야 합니다. 그렇지 않으면 결과가 일관되지 않을 수 있습니다.

고유하지 않은 열로 정렬해야 한다면, 정렬 조건에 고유한 열도 함께 추가해야 합니다.

다음은 2개 열로 `limit/offset` 페이지네이션을 구현하는 방법입니다:

<Section>
```ts copy {5}
const getUsers = async (page = 1, pageSize = 3) => {
  await db
    .select()
    .from(users)
    .orderBy(asc(users.firstName), asc(users.id)) // order by first_name (non-unique), id (pk)
    .limit(pageSize) 
    .offset((page - 1) * pageSize);
}

await getUsers();
```
</Section>

Drizzle은 `limit/offset` 페이지네이션을 쉽게 구현할 수 있게 해주는 유용한 관계형 쿼리 API를 제공합니다:

<Section>
```ts copy {7,8,9}
import * as schema from './db/schema';

const db = drizzle({ schema });

const getUsers = async (page = 1, pageSize = 3) => {
  await db.query.users.findMany({
    orderBy: (users, { asc }) => asc(users.id),
    limit: pageSize,
    offset: (page - 1) * pageSize,
  });
};

await getUsers();
```
</Section>

Drizzle은 단순하고 유연한 API를 제공하므로 사용자 정의 솔루션도 쉽게 만들 수 있습니다. `.$dynamic()` 함수를 사용해 페이지네이션을 위한 사용자 정의 함수를 만드는 방법은 다음과 같습니다:

<Section>
```ts copy {11,12,13,16}
import { SQL, asc } from 'drizzle-orm';
import { PgColumn, PgSelect } from 'drizzle-orm/pg-core';

function withPagination<T extends PgSelect>(
  qb: T,
  orderByColumn: PgColumn | SQL | SQL.Aliased,
  page = 1,
  pageSize = 3,
) {
  return qb
    .orderBy(orderByColumn)
    .limit(pageSize)
    .offset((page - 1) * pageSize);
}

const query = db.select().from(users); // query that you want to execute with pagination

await withPagination(query.$dynamic(), asc(users.id));
```

</Section>

`deferred join` 기법을 사용하면 `limit/offset` 페이지네이션의 성능을 개선할 수 있습니다. 이 방법은 전체 테이블이 아니라 데이터의 하위 집합에 대해 페이지네이션을 수행합니다.

이를 구현하려면 다음과 같이 할 수 있습니다:

```ts copy {10}
const getUsers = async (page = 1, pageSize = 10) => {
   const sq = db
    .select({ id: users.id })
    .from(users)
    .orderBy(users.id)
    .limit(pageSize)
    .offset((page - 1) * pageSize)
    .as('subquery');

   await db.select().from(users).innerJoin(sq, eq(users.id, sq.id)).orderBy(users.id);
};
```

**Benefits** of `limit/offset` 페이지네이션: 구현이 간단하고 페이지에 쉽게 접근할 수 있다는 점입니다. 즉, 이전 페이지의 상태를 저장하지 않고도 원하는 페이지로 이동할 수 있습니다.

**Drawbacks** of `limit/offset` 페이지네이션: offset이 커질수록 데이터베이스가 건너뛰기 전에 모든 행을 스캔해야 하므로 쿼리 성능이 저하되고, 데이터 이동 때문에 동일한 행이 다른 페이지에 다시 나타나거나 일부 행이 건너뛰어지는 비일관성이 발생할 수 있다는 점입니다.

다음은 어떻게 동작하는지 보여줍니다:

따라서 데이터베이스에서 실시간으로 insert와 delete 작업이 자주 발생하거나 큰 테이블을 페이지네이션할 때 높은 성능이 필요하다면, 대신 [cursor-based](/docs/guides/cursor-based-pagination) 페이지네이션을 고려해야 합니다.

`deferred join` 기법에 대해 더 자세히 알아보려면 다음 가이드를 참고하세요: [Planetscale Pagination Guide](https://planetscale.com/blog/mysql-pagination) 및 [Efficient Pagination Guide by Aaron Francis](https://aaronfrancis.com/2022/efficient-pagination-using-deferred-joins).
