이 튜토리얼에서는 [Nile Database](https://thenile.dev)와 함께 Drizzle ORM을 사용하는 방법을 보여줍니다. Nile은 멀티 테넌트 애플리케이션을 위해 다시 설계된 Postgres입니다. 

이 튜토리얼에서는 Nile의 가상 테넌트 데이터베이스로 Drizzle을 사용해 안전하고 확장 가능한 멀티 테넌트 애플리케이션을 개발하는 방법을 보여줍니다. 

이 예제 애플리케이션을 단계별로 만들어 보겠습니다. 완성된 예제를 먼저 보고 싶다면 [Github 저장소](https://github.com/niledatabase/niledatabase/tree/main/examples/quickstart/drizzle)를 살펴보세요.

<Prerequisites>
- Drizzle ORM과 [Drizzle kit](/docs/kit-overview)이 설치되어 있어야 합니다. 아래 명령을 실행하면 설치할 수 있습니다:
<Npm>
drizzle-orm
-D drizzle-kit
</Npm>
- 환경 변수 관리를 위해 `dotenv` 패키지가 설치되어 있어야 합니다. 이 패키지에 대한 자세한 내용은 [여기](https://www.npmjs.com/package/dotenv)에서 확인할 수 있습니다.
<Npm>
  dotenv
</Npm>
- Postgres 데이터베이스에 연결하기 위해 `node-postgres` 패키지가 설치되어 있어야 합니다. 이 패키지에 대한 자세한 내용은 [여기](https://www.npmjs.com/package/node-postgres)에서 확인할 수 있습니다.
<Npm>
  node-postgres
</Npm>
- 웹 프레임워크로 `express` 패키지가 설치되어 있어야 합니다. express에 대한 자세한 내용은 [여기](https://expressjs.com/)를 참고하세요.
<Npm>
  express
</Npm>

- 이 가이드는 테넌트 컨텍스트를 관리하기 위해 [AsyncLocalStorage](https://nodejs.org/api/async_context.html)를 사용합니다. 사용 중인 프레임워크나 런타임이 `AsyncLocalStorage`를 지원하지 않는다면 대체 방법은 [Drizzle\<\>Nile](../connect-nile) 문서를 참고하세요. 
</Prerequisites>

## Nile과 Drizzle ORM 설정하기

<Steps>
#### Nile에 가입하고 데이터베이스 만들기

아직 하지 않았다면 [Nile](https://console.thenile.dev)에 가입하고 앱의 안내에 따라 새 데이터베이스를 만드세요.

#### 데이터베이스 연결 문자열 가져오기

왼쪽 사이드바 메뉴에서 `"Settings"` 옵션을 선택하고 Postgres 로고를 클릭한 다음 `"generate credentials"`를 클릭합니다. 연결 문자열을 복사해서 프로젝트의 `.env` 파일에 추가하세요:

```plaintext copy
NILEDB_URL=postgres://youruser:yourpassword@us-west-2.db.thenile.dev:5432:5432/your_db_name
```

#### 데이터베이스에 Drizzle ORM 연결

`src/db` 디렉터리에 `db.ts` 파일을 만들고 데이터베이스 설정을 구성합니다:

```typescript copy filename="src/db/db.ts"
import { drizzle } from 'drizzle-orm/node-postgres';
import dotenv from "dotenv/config";
import { sql } from "drizzle-orm";
import { AsyncLocalStorage } from "async_hooks";

export const db = drizzle(process.env.NILEDB_URL);
export const tenantContext = new AsyncLocalStorage<string | undefined>();

export function tenantDB<T>(cb: (tx: any) => T | Promise<T>): Promise<T> {
  return db.transaction(async (tx) => {
    const tenantId = tenantContext.getStore();
    console.log("executing query with tenant: " + tenantId);
    // if there's a tenant ID, set it in the transaction context
    if (tenantId) {
      await tx.execute(sql`set local nile.tenant_id = '${sql.raw(tenantId)}'`);
    }

    return cb(tx);
  }) as Promise<T>;
}
```

#### Drizzle config 파일 설정

**Drizzle config**는 [Drizzle Kit](/docs/kit-overview)에서 사용되며 데이터베이스 연결, migration 폴더, 스키마 파일에 대한 모든 정보를 담고 있는 설정 파일입니다.

프로젝트 루트에 `drizzle.config.ts` 파일을 만들고 아래 내용을 추가합니다:

```typescript copy filename="drizzle.config.ts"
import 'dotenv/config';
import { defineConfig } from 'drizzle-kit';
export default defineConfig({
  out: './drizzle',
  schema: './src/db/schema.ts',
  dialect: 'postgresql',
  dbCredentials: {
    url: process.env.NILEDB_URL!,
  },
});
```

#### Nile 데이터베이스 introspect하기

Nile 데이터베이스에는 내장 테이블이 있습니다. 그중 가장 중요한 것은 테넌트를 생성하고 관리하는 데 사용하는 `tenants` 테이블입니다. 
애플리케이션에서 이 테이블을 사용하기 위해 Drizzle Kit CLI를 사용해 이 스키마를 포함한 스키마 파일을 생성하겠습니다.

```bash copy
npx drizzle-kit pull
```

introspection 결과로는 `schema.ts` 파일, 데이터베이스 스키마 스냅샷이 담긴 `meta` 폴더, migration용 sql 파일, [relational queries](/docs/rqb)를 위한 `relations.ts` 파일이 생성됩니다.

<TransferCode/>

다음은 생성된 `schema.ts` 파일의 예시입니다:

```typescript copy filename="src/db/schema.ts"
// table schema generated by introspection
import { pgTable, uuid, text, timestamp, varchar, vector, boolean } from "drizzle-orm/pg-core"
import { sql } from "drizzle-orm"

export const tenants = pgTable("tenants", {
	id: uuid().default(sql`public.uuid_generate_v7()`).primaryKey().notNull(),
	name: text(),
	created: timestamp({ mode: 'string' }).default(sql`LOCALTIMESTAMP`).notNull(),
	updated: timestamp({ mode: 'string' }).default(sql`LOCALTIMESTAMP`).notNull(),
	deleted: timestamp({ mode: 'string' }),
});
```

#### 추가 테이블 만들기

내장 테이블 외에도 애플리케이션 데이터를 저장할 테이블이 필요합니다. 이 테이블을 앞서 생성한 `src/db/schema.ts`에 추가하면 파일은 다음과 같이 됩니다:

```typescript copy filename="src/db/schema.ts"
// table schema generated by introspection
import { pgTable, uuid, text, timestamp, varchar, vector, boolean } from "drizzle-orm/pg-core"
import { sql } from "drizzle-orm"

export const tenants = pgTable("tenants", {
	id: uuid().default(sql`public.uuid_generate_v7()`).primaryKey().notNull(),
	name: text(),
	created: timestamp({ mode: 'string' }).default(sql`LOCALTIMESTAMP`).notNull(),
	updated: timestamp({ mode: 'string' }).default(sql`LOCALTIMESTAMP`).notNull(),
	deleted: timestamp({ mode: 'string' }),
});

export const todos = pgTable("todos", {
	id: uuid().defaultRandom(),
	tenantId: uuid("tenant_id"),
	title: varchar({ length: 256 }),
	estimate: varchar({ length: 256 }),
	embedding: vector({ dimensions: 3 }),
	complete: boolean(),
});
```

#### 데이터베이스에 변경 사항 적용

<ApplyChanges />

#### 웹앱 초기화

이제 Nile에 연결하도록 Drizzle을 설정했고 스키마도 준비되었으므로, 이를 멀티 테넌트 웹 애플리케이션에서 사용할 수 있습니다. 
이 예제에서는 웹 프레임워크로 Express를 사용하지만, Nile과 Drizzle은 어떤 웹 프레임워크에서도 사용할 수 있습니다.

예제를 단순하게 유지하기 위해 웹앱은 단일 파일 `src/app.ts`로 구현하겠습니다. 먼저 웹앱을 초기화합니다:

```typescript copy filename="src/app.ts"
import express from "express";
import { tenantDB, tenantContext, db } from "./db/db";
import {
  tenants as tenantSchema,
  todos as todoSchema,
} from "./db/schema";
import { eq } from "drizzle-orm";

const PORT = process.env.PORT || 3001;

const app = express();
app.listen(PORT, () => console.log(`Server is running on port ${PORT}`));
app.use(express.json());
```

#### 테넌트 인지 미들웨어 초기화

다음으로 예제에 미들웨어를 추가합니다. 이 미들웨어는 path parameter에서 테넌트 ID를 가져와 `AsyncLocalStorage`에 저장합니다. 
`src/db/index.ts`에서 만든 `tenantDB` 래퍼는 이 테넌트 ID를 사용해 쿼리 실행 시 `nile.tenant_id`를 설정하고, 
그 결과 쿼리가 해당 테넌트의 가상 데이터베이스에 대해 실행되도록 보장합니다.

```typescript copy filename="src/app.ts"
// set the tenant ID in the context based on the URL parameter
app.use('/api/tenants/:tenantId/*', (req, res, next) => {
  const tenantId = req.params.tenantId;
  console.log("setting context to tenant: " + tenantId);
  tenantContext.run(tenantId, next);
});
```

<Callout>
예제에서는 path parameter에서 tenant ID를 가져오지만, `x-tenant-id` 같은 헤더나 쿠키에 tenant ID를 설정하는 것도 일반적입니다.
</Callout>

#### 라우트 추가

마지막으로 테넌트와 todo를 생성하고 나열하기 위한 몇 가지 라우트를 추가해야 합니다. `tenantDB` 래퍼를 사용해 테넌트의 가상 데이터베이스에 연결하는 방식에 주목하세요.
또한 `app.get("/api/tenants/:tenantId/todos"`에서는 쿼리에 `where tenant_id=...`를 지정할 필요가 없었다는 점도 보세요. 
이는 우리가 해당 테넌트의 데이터베이스로 라우팅되기 때문이며, 따라서 쿼리가 다른 어떤 테넌트의 데이터도 반환할 수 없기 때문입니다.

```typescript copy filename="src/app.ts" {6,20,39,58,62,75,83}
// create new tenant
app.post("/api/tenants", async (req, res) => {
  try {
    const name = req.body.name;
    var tenants: any = null;
    tenants = await tenantDB(async (tx) => {
        return await tx.insert(tenantSchema).values({ name }).returning();
    });
    res.json(tenants);
  } catch (error: any) {
    console.log("error creating tenant: " + error.message);
    res.status(500).json({message: "Internal Server Error",});
  }
});

// return list of tenants
app.get("/api/tenants", async (req, res) => {
  let tenants: any = [];
  try {
      tenants = await tenantDB(async (tx) => {
        return await tx.select().from(tenantSchema);
      });
    res.json(tenants);
  } catch (error: any) {
    console.log("error listing tenants: " + error.message);
    res.status(500).json({message: "Internal Server Error",});
  }
});

// add new task for tenant
app.post("/api/tenants/:tenantId/todos", async (req, res) => {
  try {
    const { title, complete } = req.body;
    if (!title) {
      res.status(400).json({message: "No task title provided",});
    }
    const tenantId = req.params.tenantId;

    const newTodo = await tenantDB(async (tx) => {
      return await tx
        .insert(todoSchema)
        .values({ tenantId, title, complete })
        .returning();
    });
    // return without the embedding vector, since it is huge and useless
    res.json(newTodo);
  } catch (error: any) {
    console.log("error adding task: " + error.message);
    res.status(500).json({message: "Internal Server Error",});
  }
});

// update tasks for tenant
// No need for where clause because we have the tenant in the context
app.put("/api/tenants/:tenantId/todos", async (req, res) => {
  try {
    const { id, complete } = req.body;
    await tenantDB(async (tx) => {
      return await tx
        .update(todoSchema)
        .set({ complete })
        .where(eq(todoSchema.id, id));
    });
    res.sendStatus(200);
  } catch (error: any) {
    console.log("error updating tasks: " + error.message);
    res.status(500).json({message: "Internal Server Error",});
  }
});

// get all tasks for tenant
app.get("/api/tenants/:tenantId/todos", async (req, res) => {
  try {
    // No need for a "where" clause here because we are setting the tenant ID in the context
    const todos = await tenantDB(async (tx) => {
      return await tx
        .select({
          id: todoSchema.id,
          tenant_id: todoSchema.tenantId,
          title: todoSchema.title,
          estimate: todoSchema.estimate,
        })
        .from(todoSchema);
    });
    res.json(todos);
  } catch (error: any) {
    console.log("error listing tasks: " + error.message);
    res.status(500).json({message: error.message,});
  }
});
```

## 프로젝트 파일 구조

이것이 프로젝트의 파일 구조입니다. `src/db` 디렉터리에는 `db.ts`의 연결 설정과 `schema.ts`의 스키마 정의 같은 데이터베이스 관련 파일이 있습니다. migration과 introspection으로 생성된 파일은 `./drizzle`에 있습니다.

```plaintext
📦 <project root>
 ├ 📂 src
 │   ├ 📂 db
 │   │  ├ 📜 db.ts
 │   │  └ 📜 schema.ts
 │   └ 📜 app.ts
 ├ 📂 drizzle
 │   ├ 📂 meta
 │   │  ├ 📜 _journal.json
 │   │  └ 📜 0000_snapshot.json
 │   ├ 📜 relations.ts
 │   ├ 📜 schema.ts
 │   └ 📜 0000_watery_spencer_smythe.sql
 ├ 📜 .env
 ├ 📜 drizzle.config.ts
 └ 📜 package.json
```
