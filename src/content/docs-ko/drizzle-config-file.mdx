# Drizzle Kit 구성 파일
<Prerequisites>
- Drizzle 및 `drizzle-kit` 시작하기 - [여기를 읽으세요](/docs/get-started)
- Drizzle 스키마 기본 사항 - [여기 읽기](/docs/sql-schema-declaration)
- 데이터베이스 연결 기본 사항 - [여기를 읽어보세요](/docs/connect-overview)
- Drizzle 마이그레이션 기본 사항 - [여기에서 읽기](/docs/migrations)
- Drizzle Kit [개요](/docs/kit-overview) 및 [구성 파일](/docs/drizzle-config-file)
</Prerequisites>

Drizzle Kit를 사용하면 `TypeScript` 또는 `JavaScript` 구성 파일에서 구성 옵션을 선언할 수 있습니다.

<Section>
```plaintext {5}

 ├ ...
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 drizzle.config.ts
 └ 📜 package.json
```

<CodeTab>

```ts
export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  out: "./drizzle",
});
```
</CodeTab>

확장 구성 파일의 예
```ts collapsable
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  out: "./drizzle",
  dialect: "postgresql",
  schema: "./src/schema.ts",

  driver: "pglite",
  dbCredentials: {
    url: "./database/",
  },

  extensionsFilters: ["postgis"],
  schemaFilter: "public",
  tablesFilter: "*",

  introspect: {
    casing: "camel",
  },

  migrations: {
    prefix: "timestamp",
    table: "__drizzle_migrations__",
    schema: "public",
  },

  entities: {
    roles: {
      provider: '',
      exclude: [],
      include: []
    }
  },

  breakpoints: true,
  strict: true,
  verbose: true,
});
```

### 여러 구성 파일
프로젝트에 여러 구성 파일이 있을 수 있습니다. 이는 동일한 프로젝트에 여러 데이터베이스 단계, 여러 데이터베이스 또는 서로 다른 데이터베이스가 있는 경우 매우 유용합니다.
<Npx>
  drizzle-kit generate --config=drizzle-dev.config.ts
  drizzle-kit generate --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}

 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
```

### 마이그레이션 폴더
`out` 매개변수를 사용하면 마이그레이션을 위한 폴더를 정의할 수 있습니다. 이는 선택 사항이며 기본적으로 `drizzle`입니다.  
동일한 프로젝트의 서로 다른 데이터베이스에 대해 별도의 스키마를 많이 가질 수 있으므로 매우 유용합니다. 
서로 다른 마이그레이션 폴더가 있습니다.  
  
마이그레이션 폴더에는 `drizzle-kit`에서 사용되는 `.sql` 마이그레이션 파일이 있는 폴더가 포함되어 있습니다.

<Section>
```plaintext {3}
📦 <project root>
 ├ ...
 ├ 📂 drizzle
 │ ├ 📂 20242409125510_premium_mister_fear
 │ ├ 📜 user.ts 
 │ ├ 📜 post.ts 
 │ └ 📜 comment.ts 
 ├ 📂 src
 ├ 📜 drizzle.config.ts
 └ 📜 package.json
```
```ts {5}
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql", // "mysql" | "sqlite" | "postgresql" | "turso" | "singlestore" | "mssql"
  schema: "./src/schema/*",
  out: "./drizzle",
});
```
</Section>

### `migrations`
<rem025/>

`drizzle-kit migrate`을 실행할 때 - drizzle은 다음을 기록합니다. 
`public` 스키마(PostgreSQL에만 해당)의 `__drizzle_migrations` 로그 테이블에 있는 데이터베이스에 마이그레이션이 성공적으로 적용되었습니다.

`migrations` 구성 옵션을 사용하면 마이그레이션 로그 `table` 이름과 `schema`을 모두 변경할 수 있습니다.

|               |                      |
| :------------ | :----------------- |
| 유형 | `{ table: string, schema: string }` |
| 기본값 | `{ table: "__drizzle_migrations", schema: "drizzle" }` |
| 명령 | `migrate` |

<rem025/>
```ts
export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  migrations: {
    table: 'my-migrations-table', // `__drizzle_migrations` by default
    schema: 'public', // used in PostgreSQL only, `drizzle` by default
  },
});
```

### `extensionsFilters`
<rem025/>

[`postgis`](https://postgis.net/)과 같은 일부 확장은 데이터베이스에 설치되면 공개 스키마에 자체 테이블을 생성합니다. 
해당 테이블은 `drizzle-kit push` 또는 `drizzle-kit pull`에서 무시되어야 합니다.

`extensionsFilters` 옵션을 사용하면 Drizzle Kit에 설치된 확장 목록을 선언하여 스키마의 해당 테이블을 무시할 수 있습니다.

|               |                      |
| :------------ | :----------------- |
| 유형 | `["postgis"]` |
| 기본값 | `[]` |
| 명령 | `push` `pull` |

<rem025/>
```ts
export default defineConfig({
  dialect: "postgresql",
  extensionsFilters: ["postgis"],
});
```

### `entities`

이 구성은 데이터베이스의 특정 `entities`에 대한 관리 설정을 지정하기 위해 생성됩니다. 

현재는 `roles`만 포함되어 있지만 결국 `tables`, `schemas`, `extensions`, `functions`, `triggers` 등과 같은 모든 데이터베이스 엔터티가 여기로 마이그레이션됩니다.
#### `roles`

<rem025/>

Drizzle Kit를 사용하여 스키마, 특히 정의된 역할을 관리하는 경우 Drizzle 스키마에 정의되지 않은 일부 역할이 있는 상황이 있을 수 있습니다. 
이러한 경우 Drizzle 스키마에 각 역할을 작성하고 `.existing()`로 표시할 필요 없이 Drizzle Kit가 해당 `roles`을 건너뛰도록 할 수 있습니다.

`roles` 옵션을 사용하면 다음을 수행할 수 있습니다.

- Drizzle Kit로 역할 관리를 활성화 또는 비활성화합니다.
- Drizzle Kit의 관리에서 특정 역할을 제외합니다.
- Drizzle Kit의 관리를 위한 특정 역할을 포함합니다.
- 특정 역할을 관리하지 않는 `Neon` 및 `Supabase`과 같은 공급자에 대한 모드를 활성화합니다.
- 위의 모든 옵션을 결합하세요

|               |                       |
| :------------ | :----------------- |
| 유형 | `boolean \| { provider: "neon" \| "supabase", include: string[], exclude: string[]}`|
| 기본값 | `false` |
| 명령 | `push` `pull` `generate` |

<rem025/>

기본적으로 `drizzle-kit`은 역할을 관리하지 않으므로 이를 활성화해야 합니다. `drizzle.config.ts`에서
```ts
export default defineConfig({
  dialect: "postgresql",
  entities: {
    roles: true
  }
});
```
**귀하에게는 `admin` 역할이 있으며 관리 가능한 역할 목록에서 이를 제외하려고 합니다**
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      exclude: ['admin']
    }
  }
});
```
**귀하에게는 `admin` 역할이 있으며 관리 가능한 역할 목록에 포함하려고 합니다**
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      include: ['admin']
    }
  }
});
```
**`Neon`을 사용 중이고 `Neon`에 의해 정의된 역할을 제외하려는 경우 공급자 옵션을 사용할 수 있습니다**
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'neon'
    }
  }
});
```
**`Supabase`을 사용 중이고 `Supabase`에 의해 정의된 역할을 제외하려는 경우 공급자 옵션을 사용할 수 있습니다**
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'supabase'
    }
  }
});
```
<Callout title='중요한'>
데이터베이스 공급자가 지정한 새로운 역할에 비해 Drizzle이 약간 오래된 상황이 발생할 수 있습니다. 
따라서 `provider` 옵션과 `exclude` 추가 역할을 모두 사용해야 할 수도 있습니다. Drizzle을 사용하면 이 작업을 쉽게 수행할 수 있습니다.
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'supabase',
      exclude: ['new_supabase_role']
    }
  }
});
```
</Callout>

### `strict`
<rem025/>

`drizzle-kit push` 명령을 실행할 때 인쇄된 SQL 문을 실행하라는 확인 메시지를 표시합니다.

|               |                      |
| :------------ | :----------------- |
| 유형 | `boolean` |
| 기본값 | `false` |
| 명령 | `push` |

<rem025/>
```ts
export default defineConfig({
  dialect: "postgresql",
  strict: false,
});
```

### `verbose`
<rem025/>

`drizzle-kit push` 명령 중에 모든 SQL 문을 인쇄합니다.

|               |                      |
| :------------ | :----------------- |
| 유형 | `boolean` |
| 기본값 | `true` |
| 명령 | `generate` `pull` |

<rem025/>
```ts
export default defineConfig({
  dialect: "postgresql",
  verbose: false,
});
```

### `breakpoints`
<rem025/>

Drizzle Kit는 생성된 SQL 마이그레이션 파일에 `--> statement-breakpoint`을 자동으로 포함합니다. 
이는 하나의 트랜잭션(MySQL 및 SQLite)에서 여러 DDL 대체 문을 지원하지 않는 데이터베이스에 필요합니다.

`breakpoints` 옵션 플래그를 사용하면 켜거나 끌 수 있습니다.

|               |                      |
| :------------ | :----------------- |
| 유형 | `boolean` |
| 기본값 | `true` |
| 명령 | `generate` `pull` |

<rem025/>
```ts
export default defineConfig({
  dialect: "postgresql",
  breakpoints: false,
});
```
