## `0.21.0`으로 마이그레이션하는 방법

#### 1. drizzle-kit 명령에서 모든 `:dialect` 접두사를 제거합니다.
예: `drizzle-kit push:mysql`을 `drizzle-kit push`로 바꾸세요.

#### 2. `drizzle.config.ts` 파일을 업데이트합니다.
 - `drizzle.config.ts`에 `dialect`를 추가하세요. 이제 필수이며 `postgresql`, `mysql`, `sqlite` 중 하나여야 합니다.
 - `aws-data-api`, `turso`, `d1-http`(WIP), `expo`를 사용하는 경우에만 `drizzle.config.ts`에 `driver`를 추가하세요. 그 외의 경우에는 `drizzle.config.ts`에서 `driver`를 제거해도 됩니다.
 - `dbCredentials`에서 `connectionString` 또는 `uri`를 사용하고 있었다면 이제 `url`을 사용해야 합니다.
    
```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
    dialect: "sqlite", // "postgresql" | "mysql"
    driver: "turso", // optional and used only if `aws-data-api`, `turso`, `d1-http`(WIP) or `expo` are used
    dbCredentials: {
        url: ""
    }
})
```

#### 3. PostgreSQL 또는 SQLite를 사용하고 있고 프로젝트에 생성된 migration이 있다면 `drizzle-kit up`을 실행해 Drizzle이 모든 snapshot을 version 6으로 업그레이드하도록 하세요.

</Callout>

## Changelog

**❗ Snapshots 업그레이드**

PostgreSQL과 SQLite에서 생성된 모든 snapshot은 version 6으로 업그레이드됩니다. `drizzle-kit up`을 실행하면 업그레이드하라는 안내가 표시됩니다.

**❗ `drizzle-kit` CLI 명령에서 `:dialect` 제거**

이제는 다음과 같이 단순히 명령만 사용하면 됩니다.

- `drizzle-kit generate`
- `drizzle-kit push`
- 등

dialect를 지정할 필요가 없습니다. 이 파라미터는 `drizzle.config.ts`로 이동했습니다.

**❗ `drizzle.config` 업데이트**

- `dialect`는 이제 필수입니다. 연결할 데이터베이스 dialect를 지정하세요. 가능한 값은 `mysql`, `postgresql`, `sqlite`입니다.
- `driver`는 선택 사항이 되었고, 각 driver마다 `dbCredentials` 구성이 다릅니다. 사용 가능한 driver는 다음과 같습니다.
  - `aws-data-api`
  - `turso`
  - `d1-http` - currently WIP
  - `expo`
- `url` - 기존의 `connectionString`과 `uri`를 통합한 파라미터입니다.
- `migrations` - migrate 명령을 위해 사용자 정의 테이블과 스키마를 지정하는 새 객체 파라미터입니다.
  - `table` - drizzle이 migration을 저장할 사용자 정의 테이블
  - `schema` - drizzle이 migration을 저장할 사용자 정의 스키마(Postgres 전용)

모든 신규/업데이트된 명령의 사용 예시는 다음과 같습니다.
```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
    dialect: "sqlite", // "postgresql" | "mysql"
    driver: "turso"
    dbCredentials: {
        url: ""
    },
    migration: {
        table: "migrations",
        schema: "public"
    }
})
```

Drizzle의 driver 선택은 현재 다음 전략을 따릅니다.

`driver`가 지정되어 있으면, 해당 driver를 사용해 쿼리합니다.

`driver`가 지정되지 않은 경우:

- `postgresql` dialect에서는 Drizzle이 다음 순서로 동작합니다.
  - `pg` driver가 설치되어 있는지 확인하고, 있으면 사용합니다.
  - 없으면 `postgres` driver를 찾아 사용합니다.
  - 그래도 없으면 `@vercel/postgres`를 찾습니다.
  - 그다음 `@neondatabase/serverless`를 시도합니다.
  - 아무 것도 찾지 못하면 오류가 발생합니다.

- `mysql` dialect에서는 Drizzle이 다음 순서로 동작합니다.
  - `mysql2` driver가 설치되어 있는지 확인하고, 있으면 사용합니다.
  - 없으면 `@planetscale/database`를 찾아 사용합니다.
  - 아무 것도 찾지 못하면 오류가 발생합니다.

- `sqlite` dialect에서는 Drizzle이 다음 순서로 동작합니다.
  - `@libsql/client` driver가 설치되어 있는지 확인하고, 있으면 사용합니다.
  - 없으면 `better-sqlite3`를 찾아 사용합니다.
  - 아무 것도 찾지 못하면 오류가 발생합니다.

**❗ MySQL schemas/database는 더 이상 drizzle-kit에서 지원되지 않습니다**

Drizzle Kit은 drizzle schema 파일에 있는 추가 schemas/database에 대한 스키마 변경을 처리하지 않습니다.

# 새로운 기능

**🎉 Pull relations**

이제 Drizzle은 데이터베이스에서 foreign key 정보를 추출해 `relations` 객체로 변환하여 `relations`를 pull 합니다. introspection이 완료되면 `out` 폴더에서 `relations.ts` 파일을 확인할 수 있습니다.

relations에 대한 자세한 내용은 [문서](/docs/rqb#declaring-relations)를 확인하세요.


**🎉 생성된 migration에 대한 사용자 정의 이름**

migration 이름을 지정하려면 `--name <name>`을 사용해야 합니다.

사용법
```
drizzle-kit generate --name init_db
```

**🎉 새 명령 `migrate`**

이제 `drizzle-kit`에서 생성된 migration을 데이터베이스에 직접 적용할 수 있습니다.

사용법
```
drizzle-kit migrate
```

기본적으로 drizzle-kit은 migration 데이터 항목을 `__drizzle_migrations` 테이블에 저장하며, PostgreSQL의 경우 `drizzle` 스키마에 저장합니다. 이를 바꾸고 싶다면 `drizzle.config.ts`에서 수정 사항을 지정해야 합니다.

```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
    migrations: {
        table: "migrations",
        schema: "public"
    }
})
```
