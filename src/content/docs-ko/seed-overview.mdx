# Drizzle Seed

<IsSupportedChipGroup chips={{ 'PostgreSQL': true, 'SQLite': true, 'MySQL': true, 'SingleStore': true, 'CockroachDB': true, 'MS SQL': true }} />

<Callout type='warning'>
  `drizzle-seed`는 `drizzle-orm@0.36.4` 이상에서만 사용할 수 있습니다. 그보다 낮은 버전도 런타임에서는 동작할 수 있지만, 이 패치가 `drizzle-orm@0.36.4`에 도입되었기 때문에 타입 문제와 identity column 문제가 발생할 수 있습니다.
</Callout>

`drizzle-seed`는 데이터베이스를 채우기 위한 결정적이면서도 현실적인 가짜 데이터를 생성하도록 도와주는 TypeScript 라이브러리입니다. 시드 가능한 의사난수 생성기(pRNG)를 활용해, 생성한 데이터가 여러 실행 간에도 일관되고 재현 가능하도록 보장합니다. 이는 테스트, 개발, 디버깅에 특히 유용합니다.

#### 결정적 데이터 생성이란?

결정적 데이터 생성이란 같은 입력이 항상 같은 출력을 만들어내는 것을 의미합니다. `drizzle-seed`에서는 같은 시드 숫자로 라이브러리를 초기화하면, 매번 동일한 순서의 가짜 데이터를 생성합니다. 이를 통해 예측 가능하고 반복 가능한 데이터 세트를 만들 수 있습니다.

#### 의사난수 생성기(pRNG)

의사난수 생성기는 난수의 성질을 근사하는 숫자 시퀀스를 만들어내는 알고리즘입니다. 하지만 시드라고 하는 초기값을 기반으로 하기 때문에, 그 무작위성을 제어할 수 있습니다. 같은 시드를 사용하면 pRNG는 동일한 숫자 시퀀스를 생성하므로 데이터 생성 과정을 재현할 수 있습니다.

#### pRNG를 사용할 때의 장점:

- 일관성: 테스트가 매번 같은 데이터로 실행되도록 보장합니다.
- 디버깅: 일관된 데이터 세트를 제공해 버그를 재현하고 수정하기 쉽게 만듭니다.
- 협업: 팀원들이 시드 숫자를 공유해 같은 데이터 세트로 작업할 수 있습니다.

drizzle-seed를 사용하면 현실적인 가짜 데이터를 생성하는 능력과, 필요할 때 언제든 재현할 수 있는 제어력을 모두 얻을 수 있습니다.

## 기본 사용법

이 예제에서는 무작위 이름과 id를 가진 사용자 10명을 생성합니다.

```ts {12}
import { pgTable, integer, text } from "drizzle-orm/pg-core";
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";

const users = pgTable("users", {
  id: integer().primaryKey(),
  name: text().notNull(),
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);
  await seed(db, { users });
}

main();
```

## 옵션

**`count`**

기본적으로 `seed` 함수는 10개의 엔티티를 생성합니다. 하지만 테스트에 더 많은 데이터가 필요하다면 seed 옵션 객체에서 이를 지정할 수 있습니다.

```ts
await seed(db, schema, { count: 1000 });
```

**`seed`**

이후 실행에서 다른 값 세트를 생성하기 위한 시드가 필요하다면 `seed` 옵션에 다른 숫자를 지정할 수 있습니다. 새로운 숫자를 사용하면 고유한 값 세트가 생성됩니다.

```ts
await seed(db, schema, { seed: 12345 });
```

## 데이터베이스 초기화

`drizzle-seed`를 사용하면 예를 들어 테스트 스위트에서 데이터베이스를 쉽게 초기화하고 새 값으로 시드할 수 있습니다.

```ts
// path to a file with schema you want to reset
import * as schema from "./schema.ts";
import { reset } from "drizzle-seed";

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);
  await reset(db, schema);
}

main();
```

각 방언은 데이터베이스를 초기화하는 전략이 서로 다릅니다.

<Tabs items={['PostgreSQL', 'MySQL', 'SQLite', 'SingleStore', 'CockroachDB', 'MS SQL']}>
<Tab>
PostgreSQL의 경우 `drizzle-seed` 패키지는 `CASCADE` 옵션이 포함된 `TRUNCATE` 문을 생성하여 reset 함수를 실행한 뒤 모든 테이블이 비어 있도록 보장합니다.

```sql
TRUNCATE tableName1, tableName2, ... CASCADE;
```

</Tab>
<Tab>
MySQL의 경우 `drizzle-seed` 패키지는 다음 단계가 실패하지 않도록 먼저 `FOREIGN_KEY_CHECKS`를 비활성화한 다음, 모든 테이블의 내용을 비우기 위한 `TRUNCATE` 문을 생성합니다.

```sql
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE tableName1;
TRUNCATE tableName2;
...
SET FOREIGN_KEY_CHECKS = 1;
```

</Tab>
<Tab>
SQLite의 경우 `drizzle-seed` 패키지는 다음 단계가 실패하지 않도록 먼저 `foreign_keys` pragma를 비활성화한 다음, 모든 테이블의 내용을 비우기 위한 `DELETE FROM` 문을 생성합니다.

```sql
PRAGMA foreign_keys = OFF;
DELETE FROM tableName1;
DELETE FROM tableName2;
...
PRAGMA foreign_keys = ON;
```

</Tab>
<Tab>
SingleStore의 경우 `drizzle-seed` 패키지는 다음 단계가 실패하지 않도록 먼저 `FOREIGN_KEY_CHECKS`를 비활성화한 다음, 모든 테이블의 내용을 비우기 위한 `TRUNCATE` 문을 생성합니다.

```sql
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE tableName1;
TRUNCATE tableName2;
...
SET FOREIGN_KEY_CHECKS = 1;
```

</Tab>
<Tab>
CockroachDB의 경우 `drizzle-seed` 패키지는 `CASCADE` 옵션이 포함된 `TRUNCATE` 문을 생성하여 reset 함수를 실행한 뒤 모든 테이블이 비어 있도록 보장합니다.

```sql
TRUNCATE tableName1, tableName2, ... CASCADE;
```

</Tab>
<Tab>
MS SQL의 경우 `drizzle-seed` 패키지는 먼저 `reset` 함수의 두 번째 인수(여러분의 스키마)로 지정된 테이블을 참조하거나 그 안에 포함된 모든 foreign key 제약 조건 정보를 수집합니다.

그런 다음 해당 테이블들을 순회하면서 각 테이블과 관련된 모든 foreign key 제약 조건을 삭제하고 각 테이블을 truncate합니다.

마지막으로 패키지는 각 테이블의 원래 foreign key 제약 조건을 다시 생성합니다.

```sql
-- gather information about all fk constraints

-- drops all fk constraints related to each table
ALTER TABLE [<schemaName>].[<tableName>] DROP CONSTRAINT [<fkName>];

-- truncates each table
TRUNCATE TABLE [<schemaName>].[<tableName>];

-- recreates the original fk constraints
ALTER TABLE [<schemaName>].[<tableName>] 
ADD CONSTRAINT [<fkName>] 
FOREIGN KEY([<columnName>])
REFERENCES [<refSchemaName>].[<refTableName>] ([<refColumnName>])
ON DELETE <onDeleteAction>
ON UPDATE <onUpdateAction>;
```

</Tab>

## 세부 조정

`drizzle-seed`가 기본으로 사용하는 시드 생성기 함수의 동작을 변경해야 한다면, 직접 구현을 지정하고 시딩 과정에서 사용할 값 목록도 직접 제공할 수 있습니다.

`.refine`은 `drizzle-seed`에서 사용할 수 있는 모든 생성기 함수 목록을 받는 콜백입니다. 이 콜백은 세부 조정하려는 테이블을 키로 갖는 객체를 반환해야 하며, 필요에 따라 각 테이블의 동작을 정의합니다. 
각 테이블은 데이터베이스 시딩을 단순화하기 위해 여러 속성을 지정할 수 있습니다:

<rem025 />

- `columns`: 필요한 생성기 함수를 지정해 각 컬럼의 기본 동작을 세부 조정합니다.
- `count`: 데이터베이스에 삽입할 행 수를 지정합니다. 기본값은 10입니다. `seed()` 옵션에 전역 count가 정의되어 있더라도, 여기서 정의한 count가 해당 테이블에 대해서는 이를 덮어씁니다.
- `with`: 연관된 엔티티를 생성하고 싶을 때, 각 부모 테이블마다 얼마나 많은 참조 엔티티를 만들지 정의합니다.

<Callout title='info'>
생성할 참조 값의 개수에 대해 가중 랜덤 분포를 지정할 수도 있습니다. 이 API에 대한 자세한 내용은 [가중 랜덤 문서](#weighted-random) 섹션을 참고하세요.
</Callout>

**API**
```ts
await seed(db, schema).refine((f) => ({
  users: {
    columns: {},
    count: 10,
    with: {
        posts: 10
    }
  },
}));
```

무슨 일이 일어나는지 설명과 함께 몇 가지 예제를 살펴보겠습니다:

```ts filename='schema.ts'
import { pgTable, integer, text } from "drizzle-orm/pg-core";

export const users = pgTable("users", {
  id: integer().primaryKey(),
  name: text().notNull(),
});

export const posts = pgTable("posts", {
  id: integer().primaryKey(),
  description: text(),
  userId: integer().references(() => users.id),
});
```

**예제 1**: `users` 테이블만 20개의 엔티티로 시드하고, `name` 컬럼의 시드 로직을 세부 조정합니다.
```ts filename='index.ts'
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { users: schema.users }).refine((f) => ({
    users: {
        columns: {
            name: f.fullName(),
        },
        count: 20
    }
  }));
}

main();
```

**예제 2**: `users` 테이블을 20개의 엔티티로 시드하고, `posts` 테이블을 시드하여 `posts`에서 `users`로 참조를 만들고 각 `user`마다 10개의 `posts`를 추가합니다.
```ts filename='index.ts'
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, schema).refine((f) => ({
    users: {
        count: 20,
        with: {
            posts: 10
        }
    }
  }));
}

main();
```

**예제 3**: `users` 테이블을 5개의 엔티티로 시드하고, 이를 `users` 엔티티와 연결하지 않은 채 데이터베이스에 100개의 `posts`를 채웁니다. `users`의 `id` 생성 로직은 `10000`부터 `20000` 사이의 임의 정수를 생성하면서도 고유성을 유지하도록 조정하고, `posts`는 직접 정의한 배열에서 값을 가져오도록 세부 조정합니다.
```ts filename='index.ts'
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, schema).refine((f) => ({
    users: {
        count: 5,
        columns: {
            id: f.int({
              minValue: 10000,
              maxValue: 20000,
              isUnique: true,
            }),
        }
    },
    posts: {
        count: 100,
        columns: {
            description: f.valuesFromArray({
            values: [
                "The sun set behind the mountains, painting the sky in hues of orange and purple", 
                "I can't believe how good this homemade pizza turned out!", 
                "Sometimes, all you need is a good book and a quiet corner.", 
                "Who else thinks rainy days are perfect for binge-watching old movies?", 
                "Tried a new hiking trail today and found the most amazing waterfall!",
                // ...
            ],
          })
        }
    }
  }));
}

main();
```

<Callout type='warning'>
이 문서에서 앞으로 더 많은 가능성을 다룰 예정이지만, 지금은 이 문서의 몇몇 섹션을 먼저 살펴보시면 됩니다. 사용할 수 있는 모든 생성기 함수에 익숙해지려면 [생성기](/docs/seed-functions) 섹션을 확인하세요.

특히 훌륭한 기능 중 하나는 컬럼에 대해 생성되는 값뿐 아니라 `drizzle-seed`가 생성할 수 있는 관련 엔티티의 수를 결정할 때도 가중 랜덤화를 사용할 수 있다는 점입니다.

자세한 내용은 [가중 랜덤 문서](#weighted-random)를 확인하세요.
</Callout>


## 가중 랜덤

시드 단계에서 데이터베이스에 삽입해야 하는 데이터 세트가 여러 개이고, 각각 서로 다른 우선순위를 가져야 하는 경우가 있을 수 있습니다. 이런 경우를 위해 drizzle-seed는 weighted random이라는 API를 제공합니다.

Drizzle Seed 패키지에서 가중 랜덤을 사용할 수 있는 위치는 몇 군데 있습니다:

- 각 테이블 세부 조정 내부의 컬럼
- 생성할 관련 엔티티 수를 결정하는 `with` 속성

두 경우 모두에 대한 예제를 살펴보겠습니다:

```ts filename="schema.ts"
import { pgTable, integer, text, varchar, doublePrecision } from "drizzle-orm/pg-core";

export const orders = pgTable(
  "orders",
  {
    id: integer().primaryKey(),
    name: text().notNull(),
    quantityPerUnit: varchar().notNull(),
    unitPrice: doublePrecision().notNull(),
    unitsInStock: integer().notNull(),
    unitsOnOrder: integer().notNull(),
    reorderLevel: integer().notNull(),
    discontinued: integer().notNull(),
  }
);

export const details = pgTable(
  "details",
  {
    unitPrice: doublePrecision().notNull(),
    quantity: integer().notNull(),
    discount: doublePrecision().notNull(),

    orderId: integer()
      .notNull()
      .references(() => orders.id, { onDelete: "cascade" }),
  }
);
```

**예제 1**: `unitPrice` 생성 로직을 세부 조정하여 `5000`개의 무작위 가격을 생성하되, 10-100 사이 가격이 나올 확률은 30%, 100-300 사이 가격이 나올 확률은 70%로 만듭니다.

```ts filename="index.ts"
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, schema).refine((f) => ({
    orders: {
       count: 5000,
       columns: {
           unitPrice: f.weightedRandom(
               [
                   {
                       weight: 0.3,
                       value: funcs.int({ minValue: 10, maxValue: 100 })
                   },
                   {
                       weight: 0.7,
                       value: funcs.number({ minValue: 100, maxValue: 300, precision: 100 })
                   }
               ]
           ),
       }
    }
  }));
}

main();
```

**예제 2**: 각 주문마다 60% 확률로 1~3개의 details를, 30% 확률로 5~7개의 details를, 10% 확률로 8~10개의 details를 생성합니다.

```ts filename="index.ts"
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, schema).refine((f) => ({
    orders: {
       with: {
           details:
               [
                   { weight: 0.6, count: [1, 2, 3] },
                   { weight: 0.3, count: [5, 6, 7] },
                   { weight: 0.1, count: [8, 9, 10] },
               ]
       }
    }
  }));
}

main();
```

## 제한 사항

#### `with`에 대한 타입 제한

일부 TypeScript 제한과 현재 Drizzle API의 특성 때문에, 특히 테이블 간 순환 의존성이 존재할 때 테이블 사이의 참조를 제대로 추론하는 것은 불가능합니다.

즉, `with` 옵션에는 스키마의 모든 테이블이 표시되며, 여기서 여러분이 one-to-many 관계를 가진 테이블을 수동으로 선택해야 합니다.

<Callout title='warning'>
`with` 옵션은 one-to-many 관계에서 동작합니다. 예를 들어, 하나의 `user`와 여러 개의 `posts`가 있다면 users `with` posts는 사용할 수 있지만, posts `with` users는 사용할 수 없습니다.
</Callout>

#### Drizzle 테이블의 세 번째 파라미터에 대한 타입 제한:

현재 Drizzle 테이블의 세 번째 파라미터에 대한 타입 지원은 없습니다. 런타임에서는 동작하지만 타입 수준에서는 올바르게 동작하지 않습니다.
