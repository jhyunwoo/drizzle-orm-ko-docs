# Drizzle 스키마

Drizzle을 사용하면 기반 데이터베이스가 지원하는 다양한 모델과 속성을 TypeScript로 스키마에 정의할 수 있습니다. 
스키마를 정의하면, 이후 쿼리 수정(Drizzle-ORM 사용)과 마이그레이션(Drizzle-Kit 사용)의 source of truth 역할을 하게 됩니다.

<Callout> 
마이그레이션 과정에 Drizzle-Kit을 사용하고 있다면, Drizzle-Kit이 해당 모델들을 import해 마이그레이션 diff 과정에서 사용할 수 있도록 스키마 파일에 정의된 모든 모델을 export해야 합니다. 
</Callout>

<CodeTabs items={["import 사용", "callback 사용", "import * 사용"]}>
```ts
import { integer, pgTable, varchar } from "drizzle-orm/pg-core";

export const usersTable = pgTable("users", {
  id: integer().primaryKey().generatedAlwaysAsIdentity(),
  name: varchar().notNull(),
  age: integer().notNull(),
  email: varchar().notNull().unique(),
});
```
```ts
import { pgTable } from "drizzle-orm/pg-core";

export const usersTable = pgTable("users", (t) => ({
  id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
  name: t.varchar().notNull(),
  age: t.integer().notNull(),
  email: t.varchar().notNull().unique(),
}));
```
```ts
import * as p from "drizzle-orm/pg-core";

export const usersTable = p.pgTable("users", {
  id: p.integer().primaryKey().generatedAlwaysAsIdentity(),
  name: p.varchar().notNull(),
  age: p.integer().notNull(),
  email: p.varchar().notNull().unique(),
});
```
</CodeTabs>

## 스키마 파일 구성하기 
SQL 스키마는 TypeScript 안에서 직접 선언할 수 있으며, 하나의 `schema.ts` 파일에 모두 넣어도 되고,
여러 파일로 나눠도 됩니다. 완전히 자유롭게 구성할 수 있습니다.

#### 1개의 파일에 스키마 두기
Drizzle에서 스키마를 선언하는 가장 일반적인 방식은 모든 테이블을 하나의 `schema.ts` 파일에 넣는 것입니다.

> 참고: 스키마 파일 이름은 원하는 대로 정할 수 있습니다. 예를 들어 `models.ts`처럼 다른 이름이어도 됩니다.

이 접근 방식은 정의해야 할 테이블 모델이 너무 많지 않거나, 모두 한 파일에 두는 것이 괜찮을 때 잘 맞습니다.

예시:
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📜 schema.ts
```

`drizzle.config.ts` 파일에서는 스키마 파일의 경로를 지정해야 합니다. 이 설정을 사용하면 Drizzle이
`schema.ts` 파일을 읽고, 마이그레이션 생성 과정에서 이 정보를 사용합니다. `drizzle.config.ts` 파일과
Drizzle 마이그레이션에 대한 자세한 내용은 [link](/docs/drizzle-config-file)를 확인하세요.
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'postgresql', // 'mysql' | 'sqlite' | 'turso'
  schema: './src/db/schema.ts'
})
```

#### 여러 파일에 스키마 두기

Drizzle 모델(예: 테이블, enum, sequence 등)은 하나의 파일뿐 아니라 원하는 어떤 파일에도 둘 수 있습니다. 
단, Drizzle kit이 해당 파일들을 import해서 마이그레이션에 사용할 수 있도록, 그 파일들에서 모든 모델을 export해야 한다는 점만 보장하면 됩니다.

한 가지 사용 예는 각 테이블을 별도의 파일로 분리하는 것입니다.
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 countries.ts
          ├ 📜 cities.ts
          ├ 📜 products.ts
          ├ 📜 clients.ts
          └ 📜 etc.ts
```

`drizzle.config.ts` 파일에서는 스키마 폴더 경로를 지정해야 합니다. 이 설정을 사용하면 Drizzle이
`schema` 폴더를 읽고 모든 파일을 재귀적으로 찾아 그 안의 drizzle 테이블을 모두 가져옵니다. `drizzle.config.ts`
파일과 Drizzle 마이그레이션에 대한 자세한 내용은 [link](/docs/drizzle-config-file)를 확인하세요.

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'postgresql', // 'mysql' | 'sqlite' | 'turso'
  schema: './src/db/schema'
})
```

또한 사용자 관련 테이블, 메시징 관련 테이블, 제품 관련 테이블처럼 원하는 방식으로 그룹을 나눌 수도 있습니다. 
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 messaging.ts
          └ 📜 products.ts
```

## 데이터 스키마 구성하기

Drizzle 스키마는 사용 중인 데이터베이스의 여러 모델 타입으로 이루어집니다. Drizzle에서는 다음을 지정할 수 있습니다:
- 컬럼, 제약 조건 등을 포함한 테이블
- 스키마(PostgreSQL 전용)
- enum
- sequence(PostgreSQL 전용)
- 뷰
- 머티리얼라이즈드 뷰
- 기타 등등

하나씩 살펴보면서 Drizzle에서 스키마를 어떻게 정의해야 하는지 확인해보겠습니다.

#### **테이블과 컬럼 선언** 

Drizzle의 테이블은 데이터베이스와 마찬가지로 최소 1개의 컬럼을 가지고 정의되어야 합니다. 중요한 점이 하나 있는데,
Drizzle에는 공통 테이블 객체라는 것이 없습니다. PostgreSQL, MySQL, SQLite 중 현재 사용하는 dialect를 선택해야 합니다.

![](@/assets/images/table-structure.svg)

<CodeTabs items={["PostgreSQL 테이블", "MySQL 테이블", "SQLite 테이블"]}>
```ts copy
import { pgTable, integer } from "drizzle-orm/pg-core"

export const users = pgTable('users', {
  id: integer()
});
```
```ts copy
import { mysqlTable, int } from "drizzle-orm/mysql-core"

export const users = mysqlTable('users', {
  id: int()
});
```
```ts copy
import { sqliteTable, integer } from "drizzle-orm/sqlite-core"

export const users = sqliteTable('users', {
  id: integer()
});
```
</CodeTabs>

기본적으로 Drizzle은 데이터베이스 쿼리에서 TypeScript 키 이름을 컬럼 이름으로 사용합니다. 
따라서 위 예시의 스키마와 쿼리는 아래와 같은 SQL 쿼리를 생성합니다.

<Callout>
이 예시는 `db` 객체를 사용하지만, 이 문서에서는 그 초기화 과정을 다루지 않습니다. 데이터베이스 연결 방법은 [Connections Docs](/docs/get-started-postgresql)를 참고하세요.
</Callout>

\
**TypeScript 키 = 데이터베이스 키**
<Section>
```ts
// schema.ts
import { integer, pgTable, varchar } from "drizzle-orm/pg-core";

export const users = pgTable('users', {
  id: integer(),
  first_name: varchar()
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT "id", "first_name" from users;
```
</Section>

TypeScript 코드와 데이터베이스에서 서로 다른 이름을 사용하고 싶다면 column alias를 사용할 수 있습니다.

<Section>
```ts
// schema.ts
import { integer, pgTable, varchar } from "drizzle-orm/pg-core";

export const users = pgTable('users', {
  id: integer(),
  firstName: varchar('first_name')
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT "id", "first_name" from users;
```
</Section>

### Camel과 Snake 케이싱

데이터베이스 모델 이름은 흔히 `snake_case` 규칙을 사용하고, TypeScript에서는 모델 이름을 `camelCase`로 짓는 경우가 많습니다. 
그 결과 스키마 안에 alias 정의가 많이 생길 수 있습니다. 이를 해결하기 위해 Drizzle은 Drizzle 데이터베이스 초기화 시 optional parameter 하나를 추가해
TypeScript의 `camelCase`를 데이터베이스의 `snake_case`로 자동 매핑하는 방법을 제공합니다.

이 매핑을 위해 Drizzle DB 선언에서 `casing` 옵션을 사용할 수 있습니다. 이 파라미터를 통해
데이터베이스 모델의 명명 규칙을 지정하면, 모든 JavaScript 키를 그에 맞게 매핑하려고 시도합니다.

<Section>
```ts
// schema.ts
import { drizzle } from "drizzle-orm/node-postgres";
import { integer, pgTable, varchar } from "drizzle-orm/pg-core";

export const users = pgTable('users', {
  id: integer(),
  firstName: varchar()
})
```
```ts
// db.ts
const db = drizzle({ connection: process.env.DATABASE_URL, casing: 'snake_case' })
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT "id", "first_name" from users;
```
</Section>

### 고급 사용법

Drizzle ORM에서는 몇 가지 트릭을 사용할 수 있습니다. 
Drizzle은 전부 TypeScript 파일 안에서 동작하므로,
간단한 TypeScript 프로젝트에서 코드로 할 수 있는 일이라면 사실상 대부분 그대로 할 수 있습니다.

자주 쓰이는 기능 중 하나는 컬럼들을 여러 곳으로 분리해 두고 재사용하는 것입니다. 
예를 들어 `updated_at`, `created_at`, `deleted_at` 컬럼을 생각해 보세요. 많은 테이블/모델에서
시스템 안의 엔티티 생성, 삭제, 업데이트를 추적하고 분석하기 위해 이 세 필드가 필요할 수 있습니다.

이 컬럼들을 별도 파일에 정의해 두고, 모든 테이블 객체에 import해서 spread할 수 있습니다.

<Section>
```ts
// columns.helpers.ts
const timestamps = {
  updated_at: timestamp(),
  created_at: timestamp().defaultNow().notNull(),
  deleted_at: timestamp(),
}
```
```ts
// users.sql.ts
export const users = pgTable('users', {
  id: integer(),
  ...timestamps
})
```
```ts
// posts.sql.ts
export const posts = pgTable('posts', {
  id: integer(),
  ...timestamps
})
```
</Section>

![](@/assets/images/postgresql-db-structure.png)

`pgSchema`를 사용하면 PostgreSQL 스키마를 관리할 수 있고, 그 안에 다른 모델도 모두 배치할 수 있습니다.

Drizzle로 관리할 스키마를 정의합니다.
```ts
import { pgSchema } from "drizzle-orm/pg-core"

export const customSchema = pgSchema('custom');
```

그 다음 테이블을 스키마 객체 안에 배치합니다.
```ts {5-7}
import { integer, pgSchema } from "drizzle-orm/pg-core";

export const customSchema = pgSchema('custom');

export const users = customSchema.table('users', {
  id: integer()
})
```

### 예제

기본 개념을 이해했으니, 실제 프로젝트에 더 가깝게 보기 위해 스키마 예제를 하나 정의해 보겠습니다.

> 모든 예제는 `generateUniqueString`을 사용합니다. 구현은 모든 스키마 예제 뒤에서 제공합니다.

<CodeTabs items={['PostgreSQL', 'MySQL', 'SQLite']}>
```ts copy
import { AnyPgColumn } from "drizzle-orm/pg-core";
import { pgEnum, pgTable as table } from "drizzle-orm/pg-core";
import * as t from "drizzle-orm/pg-core";

export const rolesEnum = pgEnum("roles", ["guest", "user", "admin"]);

export const users = table(
  "users",
  {
    id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
    firstName: t.varchar("first_name", { length: 256 }),
    lastName: t.varchar("last_name", { length: 256 }),
    email: t.varchar().notNull(),
    invitee: t.integer().references((): AnyPgColumn => users.id),
    role: rolesEnum().default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = table(
  "posts",
  {
    id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
    slug: t.varchar().$default(() => generateUniqueString(16)),
    title: t.varchar({ length: 256 }),
    ownerId: t.integer("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = table("comments", {
  id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
  text: t.varchar({ length: 256 }),
  postId: t.integer("post_id").references(() => posts.id),
  ownerId: t.integer("owner_id").references(() => users.id),
});
```
```ts copy
import { mysqlTable as table } from "drizzle-orm/mysql-core";
import * as t from "drizzle-orm/mysql-core";
import { AnyMySqlColumn } from "drizzle-orm/mysql-core";

export const users = table(
  "users",
  {
    id: t.int().primaryKey().autoincrement(),
    firstName: t.varchar("first_name", { length: 256 }),
    lastName: t.varchar("last_name", { length: 256 }),
    email: t.varchar({ length: 256 }).notNull(),
    invitee: t.int().references((): AnyMySqlColumn => users.id),
    role: t.mysqlEnum(["guest", "user", "admin"]).default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = table(
  "posts",
  {
    id: t.int().primaryKey().autoincrement(),
    slug: t.varchar({ length: 256 }).$default(() => generateUniqueString(16)),
    title: t.varchar({ length: 256 }),
    ownerId: t.int("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = table("comments", {
  id: t.int().primaryKey().autoincrement(),
  text: t.varchar({ length: 256 }),
  postId: t.int("post_id").references(() => posts.id),
  ownerId: t.int("owner_id").references(() => users.id),
});
```
```ts copy
import { sqliteTable as table } from "drizzle-orm/sqlite-core";
import * as t from "drizzle-orm/sqlite-core";
import { AnySQLiteColumn } from "drizzle-orm/sqlite-core";

export const users = table(
  "users",
  {
    id: t.int().primaryKey({ autoIncrement: true }),
    firstName: t.text("first_name"),
    lastName: t.text("last_name"),
    email: t.text().notNull(),
    invitee: t.int().references((): AnySQLiteColumn => users.id),
    role: t.text().$type<"guest" | "user" | "admin">().default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = table(
  "posts",
  {
    id: t.int().primaryKey({ autoIncrement: true }),
    slug: t.text().$default(() => generateUniqueString(16)),
    title: t.text(),
    ownerId: t.int("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = table("comments", {
  id: t.int().primaryKey({ autoIncrement: true }),
  text: t.text({ length: 256 }),
  postId: t.int("post_id").references(() => posts.id),
  ownerId: t.int("owner_id").references(() => users.id),
});
```
</CodeTabs>

**`generateUniqueString` 구현:**
```ts
function generateUniqueString(length: number = 12): string {
  const characters =
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";
  let uniqueString = "";

  for (let i = 0; i < length; i++) {
    const randomIndex = Math.floor(Math.random() * characters.length);
    uniqueString += characters[randomIndex];
  }

  return uniqueString;
}
```
