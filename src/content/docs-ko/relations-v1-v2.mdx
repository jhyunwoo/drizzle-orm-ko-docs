### API 변경 사항
#### v1과 비교해 무엇이 달라졌고 다르게 동작하나요?

{/* ##### Drizzle Relations schema definition */}

가장 큰 업데이트 중 하나는 **Relations Schema definition**에 있습니다.

첫 번째 차이점은 더 이상 각 테이블마다 별도의 객체에서 따로 `relations`를 지정한 뒤, 그것들을 스키마와 함께 `drizzle()`에 모두 전달할 필요가 없다는 점입니다. Relational Queries v2에서는 필요한 모든 테이블의 관계를 한 곳에서 전용으로 지정할 수 있습니다.

콜백의 `r` 매개변수는 포괄적인 자동완성 기능을 제공합니다. 스키마의 모든 테이블은 물론 `one`, `many`, `through` 같은 함수까지 포함되므로, 관계를 정의하는 데 필요한 거의 모든 것을 한 자리에서 사용할 수 있습니다.

```ts
// relations.ts
import * as schema from "./schema"
import { defineRelations } from "drizzle-orm"

export const relations = defineRelations(schema, (r) => ({
    ...
}));
```
```ts
// index.ts
import { relations } from "./relations"
import { drizzle } from "drizzle-orm/..."

const db = drizzle(process.env.DATABASE_URL, { relations })
```

##### 무엇이 달라졌나요?

export const posts = p.pgTable('posts', {

**모든 관계를 한 곳에서 정의**

<Callout title="❌ v1">
```ts
import { relations } from "drizzle-orm/_relations";
import { users, posts } from './schema';

export const usersRelation = relations(users, ({ one, many }) => ({
  invitee: one(users, {
    fields: [users.invitedBy],
    references: [users.id],
  }),
  posts: many(posts),
}));

export const postsRelation = relations(posts, ({ one, many }) => ({
  author: one(users, {
    fields: [posts.authorId],
    references: [users.id],
  }),
}));
```
</Callout>

<Callout title='✅ v2'>
```ts
import { defineRelations } from "drizzle-orm";
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
}));
```
</Callout>

여전히 서로 다른 `parts`로 분리할 수 있고, 각 part의 크기도 원하는 대로 정할 수 있습니다.

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

그런 다음 이를 db 인스턴스에 제공할 수 있습니다.

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

**`one` 없이 `many`만 정의**

v1에서는 관계의 `many` 쪽만 필요하더라도 반대쪽에 `one`을 정의해야 했기 때문에 개발 경험이 좋지 않았습니다.

v2에서는 추가 단계 없이 `many` 쪽만 간단히 사용할 수 있습니다.

<Callout title="❌ v1">
```ts
import { relations } from "drizzle-orm/_relations";
import { users, posts } from './schema';

export const usersRelation = relations(users, ({ one, many }) => ({
  posts: many(posts),
}));

export const postsRelation = relations(posts, ({ one, many }) => ({
  author: one(users, {
    fields: [posts.authorId],
    references: [users.id],
  }),
}));
```
</Callout>

<Callout title='✅ v2'>
```ts
import { defineRelations } from "drizzle-orm";
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    posts: r.many.posts({
      from: r.users.id,
      to: r.posts.authorId,
    }),
  },
}));
```
</Callout>

**새로운 `optional` 옵션**

타입 수준에서 `optional: false`를 주면 `posts` 객체 안의 `author` 키가 필수가 됩니다.
이 옵션은 해당 엔티티가 항상 존재한다고 확신할 때 사용해야 합니다.

<Callout title="❌ v1">
v1에서는 지원되지 않았습니다.
</Callout>

<Callout title='✅ v2'>
```ts {9}
import { defineRelations } from "drizzle-orm";
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    posts: r.many.posts({
      from: r.users.id,
      to: r.posts.authorId,
      optional: false,
    }),
  },
}));
```
</Callout>

**`from`과 `to`의 업그레이드**

`fields`는 `from`으로, `references`는 `to`로 이름이 바뀌었고, 두 속성 모두 단일 값 또는 배열을 받을 수 있게 되었습니다.

<Callout title="❌ v1">
```ts
...
author: one(users, {
  fields: [posts.authorId],
  references: [users.id],
}),
...
```
</Callout>

<Callout title='✅ v2'>
```ts
... 
author: r.one.users({
  from: r.posts.authorId,
  to: r.users.id,
}),
...
```
```ts
... 
author: r.one.users({
  from: [r.posts.authorId],
  to: [r.users.id],
}),
...
```
</Callout>

export const postsRelation = relations(posts, ({ one }) => ({

**`custom types`를 위한 새로운 함수**

Relational Queries v2에서 데이터 매핑 방식을 제어할 수 있도록 custom types에 몇 가지 새로운 함수가 추가되었습니다:

<Callout collapsed='fromJson'>
선택적인 매핑 함수로, 데이터베이스에서 JSON으로 변환되어 반환된 데이터를 원하는 형식으로 다시 변환할 때 사용합니다.
예를 들어 [RQB](https://orm.drizzle.team/docs/rqb-v2) 또는 [JSON functions](https://orm.drizzle.team/docs/json-functions)를 통해 bigint 컬럼을 조회하면, 일반 쿼리처럼 bigint가 아니라 문자열 표현으로 반환됩니다.
이를 처리하려면 해당 필드의 매핑을 담당할 별도의 함수가 필요합니다:
```ts
fromJson(value: string): bigint {
	return BigInt(value);
},
```
이 함수가 있으면 반환 데이터가 다음과 같이 바뀝니다:
```ts
{
	customField: "5044565289845416380";
}
```
에서
```ts
{
	customField: 5044565289845416380n;
}
```
으로 변경됩니다.
</Callout> 
<Callout collapsed='forJsonSelect'>
선택적인 selection modifier 함수로, [JSON functions](https://orm.drizzle.team/docs/json-functions) 안에서 컬럼의 선택 방식을 수정할 때 사용합니다.
이 시나리오에서 추가로 필요한 매핑은 `fromJson` 함수를 사용해 처리할 수 있습니다.
이 함수는 [relational queries](https://orm.drizzle.team/docs/rqb-v2)에서 사용됩니다.

예를 들어 bigint를 사용할 때는 데이터 무결성을 유지하기 위해 필드를 text로 캐스팅해야 합니다.
```ts
forJsonSelect(identifier: SQL, sql: SQLGenerator, arrayDimensions?: number): SQL {
	return sql`${identifier}::text`
},
```
이렇게 하면 쿼리가 다음과 같이 바뀝니다:
```sql
SELECT
	row_to_json("t".*)
	FROM
	(
		SELECT
		"table"."custom_bigint" AS "bigint"
		FROM
		"table"
	) AS "t"
```
에서
```sql
SELECT
	row_to_json("t".*)
	FROM
	(
		SELECT
		"table"."custom_bigint"::text AS "bigint"
		FROM
		"table"
	) AS "t"
```
로 변경됩니다.
쿼리 객체가 반환하는 값도 다음처럼 바뀝니다:
```ts
{
	bigint: 5044565289845416000; // Partial data loss due to direct conversion to JSON format
}
```
에서
```ts
{
	bigint: "5044565289845416380"; // Data is preserved due to conversion of field to text before JSON-ification
}
```
으로 바뀝니다.
</Callout>

<Callout title='✅ v2'>
```ts
const customBytes = customType<{
 	data: Buffer;
 	driverData: Buffer;
 	jsonData: string;
 }>({
 	dataType: () => 'bytea',
 	fromJson: (value) => {
 		return Buffer.from(value.slice(2, value.length), 'hex');
 	},
 	forJsonSelect: (identifier, sql, arrayDimensions) =>
 		sql`${identifier}::text${sql.raw('[]'.repeat(arrayDimensions ?? 0))}`,
 });
```

</Callout>

##### 새로운 점은 무엇인가요?

**many-to-many 관계를 위한 `through`**

이전에는 junction table을 거쳐 쿼리한 뒤, 응답마다 이를 다시 매핑해야 했습니다.

이제는 그럴 필요가 없습니다!

<Callout collapsed='Schema'>
```ts
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.integer().primaryKey(),
  name: p.text(),
  verified: p.boolean().notNull(),
});

export const groups = p.pgTable("groups", {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.pgTable(
  "users_to_groups",
  {
    userId: p
      .integer("user_id")
      .notNull()
      .references(() => users.id),
    groupId: p
      .integer("group_id")
      .notNull()
      .references(() => groups.id),
  },
  (t) => [p.primaryKey({ columns: [t.userId, t.groupId] })]
);
```
</Callout>

<Callout title="❌ v1">
```ts
export const usersRelations = relations(users, ({ many }) => ({
  usersToGroups: many(usersToGroups),
}));

export const groupsRelations = relations(groups, ({ many }) => ({
  usersToGroups: many(usersToGroups),
}));

export const usersToGroupsRelations = relations(usersToGroups, ({ one }) => ({
  group: one(groups, {
    fields: [usersToGroups.groupId],
    references: [groups.id],
  }),
  user: one(users, {
    fields: [usersToGroups.userId],
    references: [users.id],
  }),
}));
```
```ts
// Query example
const response = await db.query.users.findMany({
  with: {
    usersToGroups: {
      columns: {},
      with: {
        group: true,
      },
    },
  },
});
```
</Callout>

<Callout title='✅ v2'>
```ts
import * as schema from './schema';
import { defineRelations } from 'drizzle-orm';

export const relations = defineRelations(schema, (r) => ({
  users: {
    groups: r.many.groups({
      from: r.users.id.through(r.usersToGroups.userId),
      to: r.groups.id.through(r.usersToGroups.groupId),
    }),
  },
  groups: {
    participants: r.many.users(),
  },
}));
```
```ts
// Query example

  with: {
    groups: true,
  },
});
```
</Callout>

#### 관계 스키마 정의를 v1에서 v2로 마이그레이션하는 방법

##### **옵션 1**: `drizzle-kit pull` 사용하기

새 버전의 `drizzle-kit pull`은 새로운 문법의 `relations.ts` 파일을 pull하는 기능을 지원합니다:

##### Step 1

<Npx>
drizzle-kit pull
</Npx>

#### Step 2 

생성된 관계 코드를 `drizzle/relations.ts`에서 현재 관계를 정의하는 데 사용하는 파일로 옮깁니다.
```plaintext {4-5}
 ├ 📂 drizzle
 │ ├ 📂 meta
 │ ├ 📜 migration.sql
 │ ├ 📜 relations.ts ────────┐
 │ └ 📜 schema.ts            |
 ├ 📂 src                    │ 
 │ ├ 📂 db                   │
 │ │ ├ 📜 relations.ts <─────┘
 │ │ └ 📜 schema.ts 
 │ └ 📜 index.ts         
 └ …
```

<Callout>
`drizzle/relations.ts`에는 `drizzle/schema.ts`의 모든 테이블을 import하는 구문이 포함되어 있으며, 다음과 같이 보입니다:
```ts
import * as schema from './schema'
```

이 import를 모든 스키마 테이블이 위치한 파일로 바꿔야 할 수 있습니다.

스키마 파일이 여러 개라면 다음처럼 할 수 있습니다:
```ts
import * as schema1 from './schema1'
import * as schema2 from './schema2'
...
```
</Callout>

#### Step 3

drizzle 데이터베이스 인스턴스 생성 방식을 바꾸고 `schema` 대신 `relations` 객체를 제공합니다.

<Callout title='이전'>
```ts
import * as schema from './schema'
import { drizzle } from 'drizzle-orm/...'

const db = drizzle('<url>', { schema })
```
</Callout>

<Callout title='이후'>
```ts
// should be imported from a file in Step 2
import { relations } from './relations'
import { drizzle } from 'drizzle-orm/...'

const db = drizzle('<url>', { relations })
```
</Callout>

<Callout>
MySQL dialect를 사용하고 있었다면, version 2에서 더 이상 필요하지 않은 경우 `drizzle()`에서 `mode`를 제거할 수 있습니다.
</Callout>

##### `orderBy` 구문 마이그레이션

order by는 컬럼과 정렬 방향(`asc` 또는 `desc`)을 지정하는 단일 object로 단순화되었습니다.

<Callout title="❌ v1">
```ts
const response = db._query.users.findMany({
  orderBy: (users, { asc }) => [asc(users.id)],
});
```
</Callout>

<Callout title="✅ v2">
```ts
const response = db.query.users.findMany({
  orderBy: { id: "asc" },
});
```
</Callout>

##### `many-to-many` 쿼리 마이그레이션

Relational Queries v1에서는 many-to-many 쿼리를 다루는 방식이 매우 복잡했습니다.
junction table을 통해 명시적으로 조회한 다음, 그 테이블들을 다시 매핑해야 했습니다. 예를 들면 다음과 같습니다:

```ts
const response = await db.query.users.findMany({
  with: {
    usersToGroups: {
      columns: {},
      with: {
        group: true,
      },
    },
  },
});
```

Relational Queries v2로 업그레이드한 뒤에는 many-to-many 관계가 다음과 같이 보이게 됩니다:

```ts
import * as schema from './schema';
import { defineRelations } from 'drizzle-orm';

export const relations = defineRelations(schema, (r) => ({
  users: {
    groups: r.many.groups({
      from: r.users.id.through(r.usersToGroups.userId),
      to: r.groups.id.through(r.usersToGroups.groupId),
    }),
  },
  groups: {
    participants: r.many.users(),
  },
}));
```

그리고 쿼리를 마이그레이션하면 다음과 같이 됩니다:

```ts
// Query example
const response = await db.query.users.findMany({
  with: {
    groups: true,
  },
});
```

#### Partial upgrade 또는 업그레이드 후에도 RQB v1에 머무르는 방법

이번 업그레이드는 이전 쿼리와 관계 정의를 계속 사용할 수 있도록 설계되었습니다. 즉, 한 번에 대규모 리팩터링을 하지 않고도 쿼리 단위로 코드베이스를 점진적으로 마이그레이션할 수 있습니다.

##### Step 1: relations import 변경

Relational Queries v1 방식으로 관계를 정의하려면 `drizzle-orm`에서 import해야 했습니다.

<Callout type='error' title='v1'>
```ts
import { relations } from 'drizzle-orm';
```
</Callout>

Relational Queries v2에서는 마이그레이션할 시간을 드리기 위해 이를 `drizzle-orm/_relations`로 옮겼습니다.

<Callout title='v2'>
```ts
import { relations } from "drizzle-orm/_relations";
```
</Callout>

##### Step 2: 쿼리를 `._query`로 바꾸기

Relational Queries v1을 사용하려면 `db.query.`를 작성해야 했습니다.

<Callout type='error' title='v1'>
```ts
await db.query.users.findMany();
```
</Callout>

Relational Queries v2에서는 `db.query`를 새 문법에 사용하기 위해, 기존 문법은 `db._query`로 옮겼습니다.
이렇게 해서 새 문법은 `db.query`로 유지하면서도, 기존 문법을 계속 쓰고 싶다면 `db._query`를 사용할 수 있게 했습니다.

우리는 `db.query`를 단순히 deprecated 처리하고 `db.query2`나 `db.queryV2` 같은 이름으로 바꿔야 할지 오랫동안 논의했습니다. 하지만 결국 새 API는 가능한 한 `db.query`처럼 단순하게 유지해야 하고, 기존 문법을 유지하고 싶다면 모든 쿼리를 `db._query`로 바꾸는 편이 미래의 모든 사용자에게 `db.queryV2`, `db.queryV3`, `db.queryV4` 같은 이름을 강요하는 것보다 낫다고 결론 내렸습니다.

<Callout title='v2'>
```ts
// Using RQBv1
await db._query.users.findMany();

// Using RQBv2
await db.query.users.findMany();
```
</Callout>
