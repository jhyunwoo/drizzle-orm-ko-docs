# Row-Level Security (RLS)

Drizzle을 사용하면 어떤 Postgres 테이블에서든 Row-Level Security(RLS)를 활성화하고, 다양한 옵션으로 policy를 만들고, 해당 policy가 적용될 role을 정의하고 관리할 수 있습니다.

Drizzle은 Postgres policy와 role의 raw 표현을 지원하며, 이를 원하는 방식으로 활용할 수 있습니다. 이 방식은 `Neon`, `Supabase` 같은 널리 쓰이는 Postgres 데이터베이스 제공자와 함께 동작합니다.

Drizzle에는 두 데이터베이스 제공자에 대해 RLS용으로 미리 정의된 role과 함수가 포함되어 있지만, 직접 로직을 정의할 수도 있습니다.

## RLS 활성화

<Callout type='warning' collapsed="0.x 버전에서 어떻게 동작하나요">
정책을 추가하지 않고 테이블에서 RLS만 활성화하고 싶다면 `.enableRLS()`를 사용할 수 있습니다.

PostgreSQL 문서에 따르면:

> 테이블에 policy가 하나도 없으면 기본 deny policy가 사용되며, 이 경우 어떤 row도 보이지 않거나 수정될 수 없습니다.  
> TRUNCATE나 REFERENCES처럼 전체 테이블에 적용되는 작업은 row security의 적용을 받지 않습니다.

```ts
import { integer, pgTable } from 'drizzle-orm/pg-core';

export const users = pgTable('users', {
	id: integer(),
}).enableRLS();
```
</Callout>

`v1.0.0-beta.1`부터 `.enableRLS()`는 deprecated 되었으며,
정책을 추가하지 않고 테이블에서 RLS만 활성화하고 싶다면 `pgTable.withRLS(...)`를 사용할 수 있습니다.

PostgreSQL 문서에 따르면:

> 테이블에 policy가 하나도 없으면 기본 deny policy가 사용되며, 이 경우 어떤 row도 보이지 않거나 수정될 수 없습니다.  
> TRUNCATE나 REFERENCES처럼 전체 테이블에 적용되는 작업은 row security의 적용을 받지 않습니다.

```ts
import { integer, pgTable } from 'drizzle-orm/pg-core';

export const users = pgTable.withRLS('users', {
	id: integer(),
});
```

<Callout title='important'>
테이블에 policy를 추가하면 RLS는 자동으로 활성화됩니다. 따라서 테이블에 policy를 추가할 때는 RLS를 명시적으로 활성화할 필요가 없습니다.
</Callout>

## Roles

현재 Drizzle은 아래와 같이 몇 가지 다른 옵션으로 role을 정의하는 것을 지원합니다. 더 많은 옵션에 대한 지원은 이후 릴리스에 추가될 예정입니다.

```ts
import { pgRole } from 'drizzle-orm/pg-core';

export const admin = pgRole('admin', { createRole: true, createDb: true, inherit: true });
```

role이 이미 데이터베이스에 존재하고, drizzle-kit이 이를 “보지” 않거나 migration에 포함하지 않게 하고 싶다면 해당 role을 existing으로 표시할 수 있습니다.

```ts
import { pgRole } from 'drizzle-orm/pg-core';

export const admin = pgRole('admin').existing();
```

## Policies

RLS를 제대로 활용하려면 Drizzle 테이블 안에서 policy를 정의할 수 있습니다.

<Callout title='info'>
PostgreSQL에서는 policy가 기존 테이블에 연결되어 있어야 합니다. policy는 항상 특정 테이블과 연결되므로, policy 정의는 `pgTable`의 파라미터로 정의되어야 한다고 판단했습니다.
</Callout>

**사용 가능한 모든 속성이 포함된 pgPolicy 예시**
```ts
import { sql } from 'drizzle-orm';
import { integer, pgPolicy, pgRole, pgTable } from 'drizzle-orm/pg-core';

export const admin = pgRole('admin');

export const users = pgTable('users', {
	id: integer(),
}, (t) => [
	pgPolicy('policy', {
		as: 'permissive',
		to: admin,
		for: 'delete',
		using: sql``,
		withCheck: sql``,
	}),
]);
```

**Policy 옵션**
|                          |                                                                                                                                           |
| :----------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- |
| `as`                     | 가능한 값은 `permissive` 또는 `restrictive`입니다                                                                                         |
| `to`                     | policy가 적용될 role을 지정합니다. 가능한 값은 `public`, `current_role`, `current_user`, `session_user`, 또는 문자열 형태의 다른 role 이름입니다. `pgRole` 객체를 참조할 수도 있습니다. |
| `for`                    | 이 policy가 적용될 명령을 정의합니다. 가능한 값은 `all`, `select`, `insert`, `update`, `delete`입니다.                   |
| `using`                  | policy 생성문의 `USING` 부분에 적용될 SQL 문입니다.                                              |
| `withCheck`              | policy 생성문의 `WITH CHECK` 부분에 적용될 SQL 문입니다.                                          |


**기존 테이블에 Policy 연결하기**

데이터베이스에 이미 존재하는 테이블에 policy를 연결해야 하는 상황이 있습니다.  
가장 일반적인 사례는 `Neon`이나 `Supabase` 같은 데이터베이스 제공자를 사용할 때 그들이 제공하는 기존 테이블에 policy를 추가해야 하는 경우입니다. 이럴 때는 `.link()` API를 사용할 수 있습니다.

```ts
import { sql } from "drizzle-orm";
import { pgPolicy } from "drizzle-orm/pg-core";
import { authenticatedRole, realtimeMessages } from "drizzle-orm/supabase";

export const policy = pgPolicy("authenticated role insert policy", {
  for: "insert",
  to: authenticatedRole,
  using: sql``,
}).link(realtimeMessages);
```

## Migrations

drizzle-kit으로 schema와 role을 관리하고 있다면, Drizzle schema 안에 정의되지 않은 role을 참조하고 싶을 때가 있을 수 있습니다. 이런 경우 모든 role을 Drizzle schema에 정의하고 `.existing()`을 붙이지 않고도, drizzle-kit이 이 role들을 건너뛰도록 만들고 싶을 수 있습니다.

이럴 때는 `drizzle.config.ts`에서 `entities.roles`를 사용할 수 있습니다. 전체 참조는 [`drizzle.config.ts`](docs/drizzle-config-file) 문서를 참고하세요.

기본적으로 `drizzle-kit`은 role을 관리하지 않으므로, 이 기능은 `drizzle.config.ts`에서 직접 활성화해야 합니다.

```ts {12-14}
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'postgresql',
  schema: "./drizzle/schema.ts",
  dbCredentials: {
    url: process.env.DATABASE_URL!
  },
  verbose: true,
  strict: true,
  entities: {
    roles: true
  }
});
```

추가 설정 옵션이 필요할 수도 있으므로, 몇 가지 예를 더 살펴보겠습니다.

**`admin` role이 있고 이를 관리 가능한 role 목록에서 제외하고 싶은 경우**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      exclude: ['admin']
    }
  }
});
```

**`admin` role이 있고 이를 관리 가능한 role 목록에 포함하고 싶은 경우**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      include: ['admin']
    }
  }
});
```

**`Neon`을 사용 중이고 Neon이 정의한 role을 제외하고 싶다면 provider 옵션을 사용할 수 있습니다**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'neon'
    }
  }
});
```

**`Supabase`를 사용 중이고 Supabase가 정의한 role을 제외하고 싶다면 provider 옵션을 사용할 수 있습니다**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'supabase'
    }
  }
});
```

<Callout title='important'>
데이터베이스 제공자가 새로 추가한 role에 비해 Drizzle이 약간 뒤처져 있는 상황이 있을 수 있습니다.  
이런 경우 `provider` 옵션과 함께 `exclude`로 role을 추가로 제외할 수 있습니다:

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'supabase',
      exclude: ['new_supabase_role']
    }
  }
});
```
</Callout>

## 뷰에서의 RLS

Drizzle에서는 뷰에도 RLS policy를 지정할 수 있습니다. 이를 위해서는 뷰의 WITH 옵션에 `security_invoker`를 사용해야 합니다. 아래는 간단한 예시입니다:

<Callout type='warning'>
`getColumns`는 `drizzle-orm@1.0.0-beta.2`부터 사용할 수 있습니다([여기](/docs/upgrade-v1)에서 자세히 보기)

pre-1 버전(예: `0.45.1`)을 사용 중이라면 `getTableColumns`를 사용하세요
</Callout>


```ts {5}
...

export const roomsUsersProfiles = pgView("rooms_users_profiles")
  .with({
    securityInvoker: true,
  })
  .as((qb) =>
    qb
      .select({
        ...getColumns(roomsUsers),
        email: profiles.email,
      })
      .from(roomsUsers)
      .innerJoin(profiles, eq(roomsUsers.userId, profiles.id))
  );
```

## Neon과 함께 사용하기

Neon 팀은 raw policies API 위에 감싸는 wrapper에 대한 그들의 비전을 구현하는 데 도움을 주었습니다. 우리는 미리 정의된 함수와 Neon의 기본 role을 포함하는 `crudPolicy` 함수와 함께 전용 `/neon` import를 정의했습니다.

다음은 `crudPolicy` 함수를 사용하는 예시입니다:

```ts
import { crudPolicy } from 'drizzle-orm/neon';
import { integer, pgRole, pgTable } from 'drizzle-orm/pg-core';

export const admin = pgRole('admin');

export const users = pgTable('users', {
	id: integer(),
}, (t) => [
	crudPolicy({ role: admin, read: true, modify: false }),
]);
```

이 policy는 다음과 동일합니다:

```ts
import { sql } from 'drizzle-orm';
import { integer, pgPolicy, pgRole, pgTable } from 'drizzle-orm/pg-core';

export const admin = pgRole('admin');

export const users = pgTable('users', {
	id: integer(),
}, (t) => [
	pgPolicy(`crud-${admin.name}-policy-insert`, {
		for: 'insert',
		to: admin,
		withCheck: sql`false`,
	}),
	pgPolicy(`crud-${admin.name}-policy-update`, {
		for: 'update',
		to: admin,
		using: sql`false`,
		withCheck: sql`false`,
	}),
	pgPolicy(`crud-${admin.name}-policy-delete`, {
		for: 'delete',
		to: admin,
		using: sql`false`,
	}),
	pgPolicy(`crud-${admin.name}-policy-select`, {
		for: 'select',
		to: admin,
		using: sql`true`,
	}),
]);
```

`Neon`은 미리 정의된 `authenticated`와 `anaonymous` role 및 관련 함수를 제공합니다. `Neon`에서 RLS를 사용한다면, existing으로 표시된 이 role들과 관련 함수를 RLS 쿼리에서 사용할 수 있습니다.

```ts
// drizzle-orm/neon
export const authenticatedRole = pgRole('authenticated').existing();
export const anonymousRole = pgRole('anonymous').existing();

export const authUid = (userIdColumn: AnyPgColumn) => sql`(select auth.user_id() = ${userIdColumn})`;

export const neonIdentitySchema = pgSchema('neon_identity');

export const usersSync = neonIdentitySchema.table('users_sync', {
  rawJson: jsonb('raw_json').notNull(),
  id: text().primaryKey().notNull(),
  name: text(),
  email: text(),
  createdAt: timestamp('created_at', { withTimezone: true, mode: 'string' }),
  deletedAt: timestamp('deleted_at', { withTimezone: true, mode: 'string' }),
});
```

예를 들어 `Neon`의 미리 정의된 role과 함수는 다음처럼 사용할 수 있습니다:


```ts
import { sql } from 'drizzle-orm';
import { authenticatedRole } from 'drizzle-orm/neon';
import { integer, pgPolicy, pgRole, pgTable } from 'drizzle-orm/pg-core';

export const admin = pgRole('admin');

export const users = pgTable('users', {
	id: integer(),
}, (t) => [
	pgPolicy(`policy-insert`, {
		for: 'insert',
		to: authenticatedRole,
		withCheck: sql`false`,
	}),
]);
```

## Supabase와 함께 사용하기

우리는 또한 existing으로 표시된 미리 정의 role 집합이 포함된 `/supabase` import를 제공합니다. 이를 schema에서 사용할 수 있습니다. 이 import는 향후 릴리스에서 더 많은 함수와 헬퍼가 추가되어, RLS와 `Supabase`를 더 간단하게 사용할 수 있도록 확장될 예정입니다.

```ts
// drizzle-orm/supabase
export const anonRole = pgRole('anon').existing();
export const authenticatedRole = pgRole('authenticated').existing();
export const serviceRole = pgRole('service_role').existing();
export const postgresRole = pgRole('postgres_role').existing();
export const supabaseAuthAdminRole = pgRole('supabase_auth_admin').existing();
```

예를 들어 `Supabase`의 미리 정의된 role은 다음처럼 사용할 수 있습니다:

```ts
import { sql } from 'drizzle-orm';
import { serviceRole } from 'drizzle-orm/supabase';
import { integer, pgPolicy, pgRole, pgTable } from 'drizzle-orm/pg-core';

export const admin = pgRole('admin');

export const users = pgTable('users', {
	id: integer(),
}, (t) => [
	pgPolicy(`policy-insert`, {
		for: 'insert',
		to: serviceRole,
		withCheck: sql`false`,
	}),
]);
```

`/supabase` import에는 애플리케이션에서 사용할 수 있는 미리 정의된 테이블과 함수도 포함되어 있습니다

```ts
// drizzle-orm/supabase

const auth = pgSchema('auth');
export const authUsers = auth.table('users', {
	id: uuid().primaryKey().notNull(),
});

const realtime = pgSchema('realtime');
export const realtimeMessages = realtime.table(
	'messages',
	{
		id: bigserial({ mode: 'bigint' }).primaryKey(),
		topic: text().notNull(),
		extension: text({
			enum: ['presence', 'broadcast', 'postgres_changes'],
		}).notNull(),
	},
);

export const authUid = sql`(select auth.uid())`;
export const realtimeTopic = sql`realtime.topic()`;
```

이렇게 하면 코드에서 이를 사용할 수 있고, Drizzle Kit은 이를 기존 데이터베이스로 취급하여
다른 엔티티와 연결하기 위한 정보로만 사용합니다

```ts
import { foreignKey, pgPolicy, pgTable, text, uuid } from "drizzle-orm/pg-core";
import { sql } from "drizzle-orm/sql";
import { authenticatedRole, authUsers } from "drizzle-orm/supabase";

export const profiles = pgTable(
  "profiles",
  {
    id: uuid().primaryKey().notNull(),
    email: text().notNull(),
  },
  (table) => [
    foreignKey({
      columns: [table.id],
	  // reference to the auth table from Supabase
      foreignColumns: [authUsers.id],
      name: "profiles_id_fk",
    }).onDelete("cascade"),
    pgPolicy("authenticated can view all profiles", {
      for: "select",
	  // using predefined role from Supabase
      to: authenticatedRole,
      using: sql`true`,
    }),
  ]
);
```

`Supabase`에 존재하는 테이블에 policy를 추가하는 예를 확인해 봅시다

```ts
import { sql } from "drizzle-orm";
import { pgPolicy } from "drizzle-orm/pg-core";
import { authenticatedRole, realtimeMessages } from "drizzle-orm/supabase";

export const policy = pgPolicy("authenticated role insert policy", {
  for: "insert",
  to: authenticatedRole,
  using: sql``,
}).link(realtimeMessages);
```

또한 Drizzle RLS를 Supabase와 함께 사용하는 방법과 실제 쿼리를 수행하는 방법을 보여주는 훌륭한 예제도 있습니다.  
여기에는 Supabase와의 모든 트랜잭션 작업을 처리해 줄 수 있는 훌륭한 wrapper인 `createDrizzle`도 포함되어 있습니다.  
향후 릴리스에서는 이것이 drizzle-orm/supabase로 이동하여 기본 기능처럼 사용할 수 있게 될 예정입니다

[Drizzle SupaSecureSlack repo](https://github.com/rphlmr/drizzle-supabase-rls)를 확인해 주세요

다음은 이 저장소의 구현 예시입니다
```ts
type SupabaseToken = {
  iss?: string;
  sub?: string;
  aud?: string[] | string;
  exp?: number;
  nbf?: number;
  iat?: number;
  jti?: string;
  role?: string;
};

export function createDrizzle(token: SupabaseToken, { admin, client }: { admin: PgDatabase<any>; client: PgDatabase<any> }) {
  return {
    admin,
    rls: (async (transaction, ...rest) => {
      return await client.transaction(async (tx) => {
        // Supabase exposes auth.uid() and auth.jwt()
        // https://supabase.com/docs/guides/database/postgres/row-level-security#helper-functions
        try {
          await tx.execute(sql`
          -- auth.jwt()
          select set_config('request.jwt.claims', '${sql.raw(
            JSON.stringify(token)
          )}', TRUE);
          -- auth.uid()
          select set_config('request.jwt.claim.sub', '${sql.raw(
            token.sub ?? ""
          )}', TRUE);												
          -- set local role
          set local role ${sql.raw(token.role ?? "anon")};
          `);
          return await transaction(tx);
        } finally {
          await tx.execute(sql`
            -- reset
            select set_config('request.jwt.claims', NULL, TRUE);
            select set_config('request.jwt.claim.sub', NULL, TRUE);
            reset role;
            `);
        }
      }, ...rest);
    }) as typeof client.transaction,
  };
}
```

그리고 다음처럼 사용할 수 있습니다

```ts
// https://github.com/orgs/supabase/discussions/23224
// Should be secure because we use the access token that is signed, and not the data read directly from the storage
export async function createDrizzleSupabaseClient() {
  const {
    data: { session },
  } = await createClient().auth.getSession();
  return createDrizzle(decode(session?.access_token ?? ""), { admin, client });
}

async function getRooms() {
  const db = await createDrizzleSupabaseClient();
  return db.rls((tx) => tx.select().from(rooms));
}
```
