# 버전 관리

`drizzle-seed`는 정적 데이터와 동적 데이터의 출력을 관리하기 위해 버전 관리를 사용합니다. 진정한 결정성을 보장하려면, 같은 `seed` 숫자를 사용할 때 값이 변하지 않도록 해야 합니다. 정적 데이터 소스나 동적 데이터 생성 로직이 변경되면 버전이 업데이트되며, 이전 버전을 유지할지 최신 버전을 사용할지 선택할 수 있습니다.

필요하다면 이전 버전으로 결정적 출력을 유지하면서도, 추가 생성기 같은 새 기능을 위해 최신 `drizzle-seed` 버전으로 업그레이드할 수 있습니다. 이는 새로운 기능을 사용하면서도 기존의 결정적 데이터에 의존해야 할 때 특히 유용합니다.

```ts
await seed(db, schema, { version: '2' });
```

## 히스토리
<TableWrapper>
|          API 버전  |   npm 버전    |     변경된 생성기                             |
|  :-------------- | :-------------- | :-------------                         |
|       `v1`            | `0.1.1`          |                                         |
|       `v2 (LTS) `       | `0.2.1`          |`string()`, `interval({ isUnique: true })` |
</TableWrapper>

<Callout collapsed="내부적으로 어떻게 동작하나요?">
> 이것은 실제 API 변경이 아니라, `drizzle-seed` 버전 관리를 앞으로 어떤 방식으로 진행할지 보여 주는 예시일 뿐입니다.

예를 들어 `lastName` 생성기가 변경되어, 이 생성기의 새 버전인 `V2`를 사용할 수 있게 되었다고 가정해 보겠습니다.

그 후 `firstName` 생성기가 변경되어 이 생성기의 `V3` 버전을 사용할 수 있게 되었다고 가정해 보겠습니다.

|                  |       `V1`       |      `V2`       |   `V3(latest)`   |
| :--------------: | :--------------: | :-------------: | :--------------: |
| **LastNameGen**  | `LastNameGenV1`  | `LastNameGenV2` |                  |
| **FirstNameGen** | `FirstNameGenV1` |                 | `FirstNameGenV3` |


##### 버전 3의 `firstName` 생성기와 버전 2의 `lastName` 생성기를 사용
```ts
await seed(db, schema);
```

최신 생성기 버전을 바로 사용하고 싶지 않다면, 사용할 최대 버전을 지정할 수 있습니다.

##### 버전 1의 `firstName` 생성기와 버전 2의 `lastName` 생성기를 사용
```ts
await seed(db, schema, { version: '2' });
```

##### 버전 1의 `firstName` 생성기와 버전 1의 `lastName` 생성기를 사용
```ts
await seed(db, schema, { version: '1' });
```

## 버전 2
#### 고유 `interval` 생성기가 변경되었습니다

<Callout title='업그레이드 이유'>
이전 버전의 생성기는 `1 minute 60 seconds`와 `2 minutes 0 seconds` 같은 interval을 서로 다른 값으로 생성할 수 있었습니다. 하지만 `1 minute 60 seconds` interval을 PostgreSQL 데이터베이스에 삽입하면 자동으로 `2 minutes 0 seconds`로 변환됩니다. 그 결과, 이후 `2 minutes 0 seconds` interval을 unique 컬럼에 삽입하려고 하면 오류가 발생합니다.
</Callout>

테이블에 `interval` 타입의 unique 컬럼이 포함되어 있다면 영향을 받습니다:
<Tabs items={['PostgreSQL']}>
<Tab>
```ts
import { drizzle } from "drizzle-orm/node-postgres";
import { pgTable, interval } from "drizzle-orm/pg-core";
import { seed } from "drizzle-seed";

const intervals = pgTable("intervals", {
    interval: interval().unique()
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { intervals });
}

main();
```
</Tab>
</Tabs>

아래 스크립트처럼 시딩 스크립트에서 unique `interval` 생성기를 사용하고 있다면 영향을 받습니다:
<Tabs items={['PostgreSQL', 'MySQL', 'SQLite']}>
<Tab>
```ts
import { drizzle } from "drizzle-orm/node-postgres";
import { pgTable, interval, char, varchar, text } from "drizzle-orm/pg-core";
import { seed } from "drizzle-seed";

const intervals = pgTable("intervals", {
    interval: interval().unique(),
    interval1: interval(),
    interval2: char({ length: 256 }).unique(),
    interval3: char({ length: 256 }),
    interval4: varchar().unique(),
    interval5: varchar(),
    interval6: text().unique(),
    interval7: text(),
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { intervals }).refine((f) => ({
    intervals: {
        columns: {
            interval: f.interval({ isUnique: true }),
            interval1: f.interval({ isUnique: true }),
            interval2: f.interval({ isUnique: true }),
            interval3: f.interval({ isUnique: true }),
            interval4: f.interval({ isUnique: true }),
            interval5: f.interval({ isUnique: true }),
            interval6: f.interval({ isUnique: true }),
            interval7: f.interval({ isUnique: true }),
        }
    }
  }));
}

main();
```
</Tab>

#### `string` 생성기가 변경되었습니다: non-unique와 unique 모두

<Callout title='업그레이드 이유'>
텍스트 컬럼의 길이(예: `varchar(20)`)를 기준으로 고유한 문자열을 생성할 수 있게 되었습니다.
</Callout>

테이블에 최대 길이 파라미터가 있는 텍스트 계열 타입 컬럼이나, 텍스트 계열 타입의 unique 컬럼이 포함되어 있다면 영향을 받습니다:
<Tabs items={['PostgreSQL', 'MySQL', 'SQLite']}>
<Tab>
```ts
import { drizzle } from "drizzle-orm/node-postgres";
```
