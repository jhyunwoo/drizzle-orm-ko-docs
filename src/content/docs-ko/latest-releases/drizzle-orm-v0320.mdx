# `drizzle-orm@0.32.0` 및 `drizzle-kit@0.23.0` 릴리스 노트

> 두 패키지를 모두 업그레이드하는 것이 필수는 아니지만, 쿼리와 마이그레이션 모두에서 새 기능을 사용하려면 두 패키지를 모두 업그레이드해야 합니다.

## 새 기능

### 🎉 MySQL `$returningId()` 함수

MySQL 자체는 `INSERT` 후 `RETURNING`을 네이티브로 지원하지 않습니다. `autoincrement`(또는 `serial`) 타입의 `primary keys`에 대해서만 `insertId`와 `affectedRows` 필드에 접근하는 한 가지 방법이 있습니다. 이런 경우를 Drizzle로 자동 처리하고 삽입된 모든 ID를 개별 객체로 자동으로 받을 수 있는 방식을 준비했습니다.

```ts
import { boolean, int, text, mysqlTable } from 'drizzle-orm/mysql-core';

const usersTable = mysqlTable('users', {
  id: int('id').primaryKey(),
  name: text('name').notNull(),
  verified: boolean('verified').notNull().default(false),
});


const result = await db.insert(usersTable).values([{ name: 'John' }, { name: 'John1' }]).$returningId();
//    ^? { id: number }[]
```

또한 Drizzle에서는 런타임에 사용자 정의 primary key를 생성하는 `$default` 함수로 `primary key`를 지정할 수 있습니다. `$returningId()` 호출에서 생성된 키도 함께 반환합니다.

```ts
import { varchar, text, mysqlTable } from 'drizzle-orm/mysql-core';
import { createId } from '@paralleldrive/cuid2';

const usersTableDefFn = mysqlTable('users_default_fn', {
  customId: varchar('id', { length: 256 }).primaryKey().$defaultFn(createId),
  name: text('name').notNull(),
});


const result = await db.insert(usersTableDefFn).values([{ name: 'John' }, { name: 'John1' }]).$returningId();
//  ^? { customId: string }[]
```

> primary key가 없다면 이러한 쿼리의 타입은 `{}[]`가 됩니다.

### 🎉 PostgreSQL 시퀀스

이제 Postgres에서 원하는 어떤 스키마 안에서도 sequence를 지정하고, 사용 가능한 모든 속성을 정의할 수 있습니다.

##### **예시**

```ts
import { pgSchema, pgSequence } from "drizzle-orm/pg-core";

// No params specified
export const customSequence = pgSequence("name");

// Sequence with params
export const customSequence = pgSequence("name", {
      startWith: 100,
      maxValue: 10000,
      minValue: 100,
      cycle: true,
      cache: 10,
      increment: 2
});

// Sequence in custom schema
export const customSchema = pgSchema('custom_schema');

export const customSequence = customSchema.sequence("name");
```

### 🎉 PostgreSQL identity columns

[Source](https://wiki.postgresql.org/wiki/Don%27t_Do_This#Don.27t_use_serial): 언급했듯이 Postgres의 `serial` 타입은 오래되었으며 deprecated되어야 합니다. 이상적으로는 사용하지 않는 것이 좋습니다. `Identity columns`는 스키마에서 sequence를 지정하는 권장 방식이므로, 이번에 `identity columns` 기능을 도입합니다.

##### **예시**

```ts
import { pgTable, integer, text } from 'drizzle-orm/pg-core' 

export const ingredients = pgTable("ingredients", {
  id: integer("id").primaryKey().generatedAlwaysAsIdentity({ startWith: 1000 }),
  name: text("name").notNull(),
  description: text("description"),
});
```

`.generatedAlwaysAsIdentity()` 함수에서 sequence에 사용할 수 있는 모든 속성을 지정할 수 있습니다. 또한 이러한 sequence에 사용자 정의 이름도 지정할 수 있습니다.

PostgreSQL docs [reference](https://www.postgresql.org/docs/current/sql-createtable.html#SQL-CREATETABLE-PARMS-GENERATED-IDENTITY).

### 🎉 PostgreSQL generated columns

이제 PostgreSQL이 지원하는 어떤 컬럼에서도 generated columns를 사용하기 위해 generated columns를 지정할 수 있습니다.

##### **예시** `tsvector`용 생성 컬럼

> 참고: `tsVector` 컬럼 타입은 정식 릴리스 전에 추가할 예정입니다.

```ts
import { SQL, sql } from "drizzle-orm";
import { customType, index, integer, pgTable, text } from "drizzle-orm/pg-core";

const tsVector = customType<{ data: string }>({
  dataType() {
    return "tsvector";
  },
});

export const test = pgTable(
  "test",
  {
    id: integer("id").primaryKey().generatedAlwaysAsIdentity(),
    content: text("content"),
    contentSearch: tsVector("content_search", {
      dimensions: 3,
    }).generatedAlwaysAs(
      (): SQL => sql`to_tsvector('english', ${test.content})`
    ),
  },
  (t) => ({
    idx: index("idx_content_search").using("gin", t.contentSearch),
  })
);
```

테이블의 컬럼을 참조할 필요가 없다면 `sql` 템플릿이나 `string`만 사용할 수 있습니다.

```ts
export const users = pgTable("users", {
  id: integer("id"),
  name: text("name"),
  generatedName: text("gen_name").generatedAlwaysAs(sql`hello world!`),
  generatedName1: text("gen_name1").generatedAlwaysAs("hello world!"),
}),
```

### 🎉 MySQL generated columns

이제 MySQL이 지원하는 어떤 컬럼에서도 generated columns를 사용하기 위해 generated columns를 지정할 수 있습니다.

`stored`와 `virtual` 옵션을 모두 지정할 수 있으며, 자세한 내용은 [MySQL docs](https://dev.mysql.com/doc/refman/8.4/en/create-table-generated-columns.html)에서 확인할 수 있습니다.

또한 MySQL은 이러한 컬럼 사용에 대해 몇 가지 제한이 있으며, 이는 [여기](https://dev.mysql.com/doc/refman/8.4/en/alter-table-generated-columns.html)에 설명되어 있습니다.

Drizzle Kit의 `push` 명령에도 제한이 있습니다.

1. `push`를 사용해서는 generated constraint expression과 type을 변경할 수 없습니다. drizzle-kit은 이 변경을 무시합니다. 이를 동작시키려면 `drop the column`을 하고, `push`한 뒤, `add a column with a new expression`을 해야 합니다. 이는 데이터베이스 쪽의 복잡한 매핑 때문으로, 스키마 표현식이 데이터베이스 쪽에서 수정되고 introspection 시 다른 문자열을 얻게 되기 때문입니다. 이 표현식을 여러분이 바꾼 것인지, 아니면 데이터베이스가 바꾸고 포맷한 것인지 확신할 수 없습니다. generated columns이고 `push`가 주로 로컬 데이터베이스에서 프로토타이핑할 때 사용된다는 점을 고려하면, generated columns를 `drop`하고 `create`하는 것은 빠를 것입니다. 이 컬럼들은 `generated`이므로 모든 데이터는 복원됩니다.

2. `generate`에는 제한이 없어야 합니다.

##### **예시**

```ts
export const users = mysqlTable("users", {
  id: int("id"),
  id2: int("id2"),
  name: text("name"),
  generatedName: text("gen_name").generatedAlwaysAs(
    (): SQL => sql`${schema2.users.name} || 'hello'`,
    { mode: "stored" }
  ),
  generatedName1: text("gen_name1").generatedAlwaysAs(
    (): SQL => sql`${schema2.users.name} || 'hello'`,
    { mode: "virtual" }
  ),
}),
```

테이블의 컬럼을 참조할 필요가 없다면 `.generatedAlwaysAs()` 안에서 `sql` 템플릿이나 `string`만 사용해도 됩니다.

### 🎉 SQLite generated columns

이제 SQLite가 지원하는 어떤 컬럼에서도 generated columns를 사용하기 위해 generated columns를 지정할 수 있습니다.

`stored`와 `virtual` 옵션을 모두 지정할 수 있으며, 자세한 내용은 [SQLite docs](https://www.sqlite.org/gencol.html)에서 확인할 수 있습니다.

또한 SQLite는 이러한 컬럼 사용에 대해 몇 가지 제한이 있으며, 이는 [여기](https://www.sqlite.org/gencol.html)에 설명되어 있습니다.

Drizzle Kit의 `push` 및 `generate` 명령에도 제한이 있습니다.

1. 기존 테이블에서 stored 타입의 generated constraint expression은 변경할 수 없습니다. 이 경우 테이블을 삭제하고 다시 생성해야 합니다. 이는 이러한 동작에 대한 SQLite의 제한 때문입니다. 이 경우는 향후 릴리스에서 처리할 예정이며(데이터 마이그레이션과 함께 새 테이블을 생성하는 방식이 될 것입니다).

2. 위와 같은 이유로 기존 컬럼에 `stored` generated expression을 추가할 수 없습니다. 하지만 기존 컬럼에 `virtual` expression을 추가하는 것은 가능합니다.

3. 위와 같은 이유로 기존 컬럼의 `stored` generated expression을 변경할 수 없습니다. 하지만 `virtual` expression은 변경할 수 있습니다.

4. 위와 같은 이유로 generated constraint type을 `virtual`에서 `stored`로 변경할 수 없습니다. 하지만 `stored`에서 `virtual`로 변경하는 것은 가능합니다.

## 새로운 Drizzle Kit 기능

### 🎉 새로운 모든 orm 기능에 대한 마이그레이션 지원

PostgreSQL sequences, identity columns, 그리고 모든 dialect의 generated columns를 지원합니다.

### 🎉 `drizzle-kit push`를 위한 새 플래그 `--force`

push 명령을 사용할 때 모든 data-loss 문을 자동 승인할 수 있습니다. 이 기능은 CLI 파라미터에서만 사용할 수 있습니다. 데이터베이스에서 data-loss 문을 실행해도 괜찮다면 항상 이 옵션을 사용하세요.

### 🎉 새로운 `migrations` 플래그 `prefix`

이제 migration 파일 접두사를 원하는 대로 사용자 지정해 migration 도구 형식에 맞출 수 있습니다.

- `index`는 기본 타입이며 `0001_name.sql` 파일명을 생성합니다.
- `supabase`와 `timestamp`는 동일하며 `20240627123900_name.sql` 파일명을 생성합니다.
- `unix`는 `1719481298_name.sql` 형식의 unix seconds 접두사를 생성합니다.
- `none`은 접두사를 완전히 생략합니다.


##### **예시**: Supabase migrations 형식
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  migrations: {
    prefix: 'supabase'
  }
});

```
