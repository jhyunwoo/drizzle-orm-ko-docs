> Drizzle ORM `0.29.0` 버전은 최소 `0.20.0` 버전의 Drizzle Kit을 요구하며, 그 반대도 마찬가지입니다. 따라서 더 새로운 Drizzle ORM 버전으로 업그레이드할 때는 Drizzle Kit도 함께 업그레이드해야 합니다. 특히 Drizzle Kit을 업그레이드해야 하고 Drizzle ORM 버전이 `<0.28.0`보다 오래된 경우, 버전 전반에 걸쳐 일부 breaking change가 발생할 수 있습니다.

## 새 기능

### 🎉 MySQL `bigint`용 `unsigned` 옵션

이제 `bigint unsigned` 타입을 지정할 수 있습니다.

```ts copy {2}
const table = mysqlTable('table', {
  id: bigint('id', { mode: 'number', unsigned: true }),
});
```

[docs](/docs/column-types/mysql#bigint)에서 더 자세히 읽어보세요.

### 🎉 향상된 query builder 타입

`0.29.0`부터 기본적으로, Drizzle의 모든 query builder는 SQL을 가능한 한 그대로 따르도록 설계되어 있기 때문에 대부분의 메서드는 한 번만 호출할 수 있습니다. 예를 들어 SELECT 문에는 WHERE 절이 하나만 있을 수 있으므로 `.where()`도 한 번만 호출할 수 있습니다.

```ts copy {5}
const query = db
  .select()
  .from(users)
  .where(eq(users.id, 1))
  .where(eq(users.name, 'John')); // ❌ Type error - where() can only be invoked once
```

이 동작은 한 번에 전체 쿼리를 만드는 일반적인 쿼리 작성 방식에는 유용합니다. 하지만 쿼리를 동적으로 조립하고 싶을 때, 즉 query builder를 받아 쿼리를 확장하는 공용 함수가 있을 때는 문제가 됩니다. 이 문제를 해결하기 위해 Drizzle은 query builder용 특별한 'dynamic' 모드를 제공하며, 이 모드에서는 메서드를 한 번만 호출해야 한다는 제한이 제거됩니다. 이를 활성화하려면 query builder에서 `.$dynamic()`을 호출해야 합니다.

제공된 페이지 번호와 선택적인 페이지 크기를 기반으로 쿼리에 LIMIT와 OFFSET 절을 추가하는 간단한 withPagination 함수를 구현해서 동작 방식을 살펴보겠습니다.

```ts copy {12,13}
function withPagination<T extends PgSelect>(
  qb: T,
  page: number,
  pageSize: number = 10,
) {
  return qb.limit(pageSize).offset(page * pageSize);
}

const query = db.select().from(users).where(eq(users.id, 1));
withPagination(query, 1); // ❌ Type error - the query builder is not in dynamic mode

const dynamicQuery = query.$dynamic();
withPagination(dynamicQuery, 1); // ✅ OK
```

withPagination 함수는 제네릭이므로, 예를 들어 조인을 추가해 그 안에서 query builder의 결과 타입을 수정할 수 있다는 점에 유의하세요.

```ts copy {2}
function withFriends<T extends PgSelect>(qb: T) {
  return qb.leftJoin(friends, eq(friends.userId, users.id));
}

let query = db.select().from(users).where(eq(users.id, 1)).$dynamic();
query = withFriends(query);
```

[docs](/docs/dynamic-query-building)에서 더 자세히 읽어보세요.

### 🎉 primary key와 foreign key 이름 지정 기능

제약 조건 이름이 데이터베이스의 64자 제한을 초과할 때 문제가 생깁니다. 이 경우 데이터베이스 엔진이 이름을 잘라내기 때문에 잠재적으로 문제가 발생할 수 있습니다. `0.29.0`부터는 `primaryKey()`와 `foreignKey()` 모두에 대해 사용자 정의 이름을 지정할 수 있습니다. 또한 기존 `primaryKey()` 문법은 더 이상 권장되지 않으며, 여전히 사용할 수는 있지만 향후 릴리스에서 제거될 예정입니다.

```ts copy {5,7}
const table = pgTable('table', {
  id: integer('id'),
  name: text('name'),
}, (table) => ({
  cpk: primaryKey({ name: 'composite_key', columns: [table.id, table.name] }),
  cfk: foreignKey({
    name: 'fkName',
    columns: [table.id],
    foreignColumns: [table.name],
  }),
}));
```

[docs](/docs/indexes-constraints#composite-primary-key)에서 더 자세히 읽어보세요.

### 🎉 Read Replicas 지원

이제 Drizzle의 `withReplica` 함수를 사용해 읽기 복제본용 데이터베이스 연결과 쓰기 작업용 메인 인스턴스를 각각 지정할 수 있습니다. 기본적으로 `withReplicas`는 읽기 작업에는 무작위 읽기 복제본을 사용하고, 그 외 모든 데이터 변경 작업에는 메인 인스턴스를 사용합니다. 어떤 읽기 복제본 연결을 사용할지 결정하는 사용자 정의 로직도 지정할 수 있습니다. 가중치를 주거나 원하는 어떤 방식으로든 자유롭게 결정할 수 있습니다. 다음은 사용 예시입니다.

```ts copy {5}
const primaryDb = drizzle({ client });
const read1 = drizzle({ client });
const read2 = drizzle({ client });

const db = withReplicas(primaryDb, [read1, read2]);

// read from primary
db.$primary.select().from(usersTable);

// read from either read1 connection or read2 connection
db.select().from(usersTable)

// use primary database for delete operation
db.delete(usersTable).where(eq(usersTable.id, 1))
```

첫 번째 복제본이 70%, 두 번째 복제본이 30% 확률로 선택되도록 읽기 복제본을 선택하는 사용자 정의 로직 구현 예시입니다. 읽기 복제본에 대해 어떤 종류의 랜덤 선택 로직이든 구현할 수 있다는 점에 유의하세요.

```ts copy
const db = withReplicas(primaryDb, [read1, read2], (replicas) => {
    const weight = [0.7, 0.3];
    let cumulativeProbability = 0;
    const rand = Math.random();

    for (const [i, replica] of replicas.entries()) {
      cumulativeProbability += weight[i]!;
      if (rand < cumulativeProbability) return replica;
    }
    return replicas[0]!
});
```

`withReplicas` 함수는 Drizzle ORM의 모든 dialect에서 사용할 수 있습니다.

[docs](/docs/read-replicas)에서 더 자세히 읽어보세요.

### 🎉 Set operators 지원 (UNION, UNION ALL, INTERSECT, INTERSECT ALL, EXCEPT, EXCEPT ALL)

API 논의부터 적절한 타입 검사와 런타임 로직, 광범위한 테스트 세트에 이르기까지 큰 기여를 해준 @Angelelz에게 진심으로 감사드립니다. 덕분에 이번 릴리스에서 이 기능을 제공할 수 있었습니다.

사용 예시:
모든 set operator는 `import approach`와 `builder approach` 두 가지 방식으로 사용할 수 있습니다.

<Section>
```ts copy {2,7}
// Import approach
import { union } from 'drizzle-orm/pg-core'

const allUsersQuery = db.select().from(users);
const allCustomersQuery = db.select().from(customers);

const result = await union(allUsersQuery, allCustomersQuery)
```

```ts copy {2}
// Builder approach
const result = await db.select().from(users).union(db.select().from(customers));
```
</Section>

[docs](/docs/set-operations)에서 더 자세히 읽어보세요.

### 🎉 새로운 MySQL Proxy Driver

새 드라이버가 릴리스되어 MySQL 데이터베이스를 사용하는 HTTP 드라이버를 직접 구현할 수 있게 되었습니다. 사용 예시는 `./examples/mysql-proxy` 폴더에서 확인할 수 있습니다.

쿼리와 마이그레이션에 사용할 두 개의 엔드포인트를 서버에 구현해야 합니다(마이그레이션 엔드포인트는 선택 사항이며 drizzle migrations를 사용하려는 경우에만 필요합니다). 서버와 드라이버 구현은 모두 사용자에게 달려 있으므로 어떤 제약도 없습니다. 사용자 정의 매핑, 로깅 등도 얼마든지 추가할 수 있습니다.

서버와 드라이버 구현 예시는 모두 `./examples/mysql-proxy` 폴더에서 찾을 수 있습니다.

```ts copy {4,9}
// Driver
import axios from 'axios';
import { eq } from 'drizzle-orm/expressions';
import { drizzle } from 'drizzle-orm/mysql-proxy';
import { migrate } from 'drizzle-orm/mysql-proxy/migrator';
import { cities, users } from './schema';

async function main() {
  const db = drizzle(async (sql, params, method) => {
    try {
      const rows = await axios.post(`${process.env.REMOTE_DRIVER}/query`, {
        sql,
        params,
        method,
      });

      return { rows: rows.data };
    } catch (e: any) {
      console.error('Error from pg proxy server:', e.response.data);
      return { rows: [] };
    }
  });

  await migrate(db, async (queries) => {
    try {
      await axios.post(`${process.env.REMOTE_DRIVER}/migrate`, { queries });
    } catch (e) {
      console.log(e);
      throw new Error('Proxy server cannot run migrations');
    }
  }, { migrationsFolder: 'drizzle' });

  await db.insert(cities).values({ id: 1, name: 'name' });

  await db.insert(users).values({
    id: 1,
    name: 'name',
    email: 'email',
    cityId: 1,
  });

  const usersToCityResponse = await db.select().from(users).leftJoin(
    cities,
    eq(users.cityId, cities.id),
  );
}
```

[docs](/docs/get-started-mysql#http-proxy)에서 더 자세히 읽어보세요.

### 🎉 새로운 PostgreSQL Proxy Driver

MySQL과 마찬가지로 이제 PostgreSQL 데이터베이스용 자체 http 드라이버를 구현할 수 있습니다. 사용 예시는 `./examples/pg-proxy` 폴더에서 확인할 수 있습니다.

쿼리와 마이그레이션에 사용할 두 개의 엔드포인트를 서버에 구현해야 합니다(마이그레이션 엔드포인트는 선택 사항이며 drizzle migrations를 사용하려는 경우에만 필요합니다). 서버와 드라이버 구현은 모두 사용자에게 달려 있으므로 어떤 제약도 없습니다. 사용자 정의 매핑, 로깅 등도 얼마든지 추가할 수 있습니다.

서버와 드라이버 구현 예시는 모두 `./examples/pg-proxy` 폴더에서 찾을 수 있습니다.

```ts copy {3,8}
import axios from 'axios';
import { eq } from 'drizzle-orm/expressions';
import { drizzle } from 'drizzle-orm/pg-proxy';
import { migrate } from 'drizzle-orm/pg-proxy/migrator';
import { cities, users } from './schema';

async function main() {
  const db = drizzle(async (sql, params, method) => {
    try {
      const rows = await axios.post(`${process.env.REMOTE_DRIVER}/query`, { sql, params, method });

      return { rows: rows.data };
    } catch (e: any) {
      console.error('Error from pg proxy server:', e.response.data);
      return { rows: [] };
    }
  });

  await migrate(db, async (queries) => {
    try {
      await axios.post(`${process.env.REMOTE_DRIVER}/query`, { queries });
    } catch (e) {
      console.log(e);
      throw new Error('Proxy server cannot run migrations');
    }
  }, { migrationsFolder: 'drizzle' });

  const insertedCity = await db.insert(cities).values({ id: 1, name: 'name' }).returning();
  const insertedUser = await db.insert(users).values({ id: 1, name: 'name', email: 'email', cityId: 1 });
  const usersToCityResponse = await db.select().from(users).leftJoin(cities, eq(users.cityId, cities.id));
}
```

[docs](/docs/get-started-postgresql#http-proxy)에서 더 자세히 읽어보세요.

### 🎉 `D1` Batch API 지원

참고: https://developers.cloudflare.com/d1/platform/client-api/#dbbatch

Batch API 사용 예시:

<Section>
```ts copy {1}
const batchResponse = await db.batch([
  db.insert(usersTable).values({ id: 1, name: 'John' }).returning({
    id: usersTable.id,
  }),
  db.update(usersTable).set({ name: 'Dan' }).where(eq(usersTable.id, 1)),
  db.query.usersTable.findMany({}),
  db.select().from(usersTable).where(eq(usersTable.id, 1)),
  db.select({ id: usersTable.id, invitedBy: usersTable.invitedBy }).from(
    usersTable,
  ),
]);
```

```ts
type BatchResponse = [
  {
    id: number;
  }[],
  D1Result,
  {
    id: number;
    name: string;
    verified: number;
    invitedBy: number | null;
  }[],
  {
    id: number;
    name: string;
    verified: number;
    invitedBy: number | null;
  }[],
  {
    id: number;
    invitedBy: number | null;
  }[],
];
```
</Section>

`db.batch` 안에서 사용할 수 있는 모든 builder는 다음과 같습니다.

```ts
`db.all()`,
`db.get()`,
`db.values()`,
`db.run()`,
`db.query.<table>.findMany()`,
`db.query.<table>.findFirst()`,
`db.select()...`,
`db.update()...`,
`db.delete()...`,
`db.insert()...`,
```

더 많은 사용 예시는 [integration-tests/tests/d1-batch.test.ts](https://github.com/drizzle-team/drizzle-orm/blob/beta/integration-tests/tests/d1-batch.test.ts)와 [docs](/docs/batch-api)에서 확인할 수 있습니다.

## Drizzle Kit 0.20.0

1. `defineConfig` 함수를 사용해 drizzle.config를 정의하는 새로운 방식
2. wrangler.toml 파일을 사용해 Drizzle Studio에서 Cloudflare D1에 접근하는 기능
3. Drizzle Studio가 https://local.drizzle.studio/ 로 이전 중
4. `bigint unsigned` 지원
5. `primaryKeys`와 `foreignKeys`에 사용자 정의 이름 지정 가능
6. 환경 변수를 이제 자동으로 가져옴
7. 일부 버그 수정 및 개선

drizzle-kit 업데이트에 대해서는 [여기](https://github.com/drizzle-team/drizzle-kit-mirror/releases/tag/v0.20.0)에서 더 읽어볼 수 있습니다.
