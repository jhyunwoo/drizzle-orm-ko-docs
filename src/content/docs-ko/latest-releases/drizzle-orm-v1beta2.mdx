# 새 기능

## MSSQL 다이얼렉트

이제 Drizzle은 `drizzle-orm`, `drizzle-kit`, `drizzle-seed` 패키지에서 MSSQL을 지원합니다. 대부분의 컬럼, query builder 기능, migration 전략 등을 지원합니다.

아직 지원되지 않는 유일한 기능은 `RQBv2`입니다.

```ts
// Make sure to install the 'mssql' package 
import { drizzle } from 'drizzle-orm/node-mssql';

const db = drizzle(process.env.DATABASE_URL);
 
const result = await db.execute('select 1');
```
```ts
// Make sure to install the 'pg' package 
import { drizzle } from 'drizzle-orm/node-mssql';

// You can specify any property from the mssql connection options
const db = drizzle({ 
  connection: { 
    connectionString: process.env.DATABASE_URL,
    ssl: true
  }
});
 
const result = await db.execute('select 1');
```

## 관계형 쿼리 파트

relations 설정을 여러 부분으로 분리해야 하는 경우 `defineRelationsPart` helper를 사용할 수 있습니다.

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";
export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));
export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

그런 다음 이를 db 인스턴스에 전달할 수 있습니다.

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

## Folders v3 마이그레이션

> 연결된 논의: https://github.com/drizzle-team/drizzle-orm/discussions/2832

마이그레이션 폴더 구조를 다음과 같이 업데이트했습니다.
- journal.json 제거
- SQL 파일과 snapshot을 각각 별도의 migration 폴더로 그룹화
- `drizzle-kit drop` 명령 제거

이 변경으로 journal 파일로 인한 잠재적인 Git 충돌을 없애고, 충돌 난 migration을 삭제하거나 수정하는 과정을 단순화했습니다.

다가오는 beta 릴리스에서는 commutativity checks를 도입해 팀 migration 충돌을 안내하고, 가능한 충돌을 감지하며, 해결 방법을 제안할 예정입니다.
> Commutativity discussion: https://github.com/drizzle-team/drizzle-orm/discussions/5005

이전 폴더를 새 형식으로 마이그레이션하려면 다음을 실행해야 합니다.
```
drizzle-kit up
```

## 전체 `drizzle-kit` 재작성

주요 kit 및 migration 이슈를 해결하기 위한 아키텍처 재작성입니다. 더 빠르게 반복하고, 테스트 커버리지를 개선하며, 전반적인 안정성을 높이는 데 도움이 되는 가치 있고 필요한 업데이트 세트를 완료했습니다.

완료된 작업 요약:
- 데이터베이스 snapshot에서 데이터베이스 DDL snapshot으로 이전
- diff 감지 및 적용을 위한 전체 아키텍처 재작업
- 기본값, 표현식, 타입 감지에 대한 대폭적인 개선 추가
- 데이터베이스 호출과 쿼리 복잡도를 최소화하여 스키마 introspection 시간을 10초에서 1초 미만으로 단축
- push를 위한 query hints 및 explain 지원 추가
- 테스트 커버리지 확대 - 각 테스트 케이스는 이제 최대 6가지 시나리오(push+push, pull+generate 등)를 실행

## `drizzle-kit pull --init` 추가

이 플래그는 데이터베이스에 drizzle migration 테이블을 생성하고, 처음 pull한 migration을 applied 상태로 표시하여 그 지점부터 계속 작업할 수 있게 해줍니다.

## `schemaFilter` 동작 업데이트

`drizzle-kit`은 이제 코드에 정의된 모든 스키마를 관리하기 시작합니다. 이를 필터링하고 싶다면 `schemaFilter`를 사용할 수 있습니다.
이전에는 `schemaFilter`에 추가 스키마를 명시적으로 넣지 않는 한 public 스키마만 관리했습니다.

이제 glob pattern도 지원하므로 원하는 방식으로 스키마를 필터링할 수 있습니다.

## `.enableRLS()` 사용 중단

이전에는 RLS가 활성화된 PostgreSQL 테이블을 표시하려면 다음과 같이 해야 했습니다.

```ts
// OLD syntax
pgTable('name', {}).enableRLS()
``` 

이 옵션은 다른 위치로 옮겼습니다.

```ts
pgTable.withRLS('users', {});
```

## 컬럼에 직접 alias 지정

이제 컬럼에 `as` alias를 더 간단하게 추가할 수 있습니다.

```
const query = db
	.select({ age: users.age.as('ageOfUser'), id: users.id.as('userId') })
	.from(users)
	.orderBy(asc(users.id.as('userId')));
```
