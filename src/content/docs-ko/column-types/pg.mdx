이들 모두에 대해 기본 지원을 제공하지만, 그것만으로 충분하지 않다면 **[custom types](/docs/custom-types)**를 자유롭게 만들어 사용할 수 있습니다.

<Callout title='중요' type='warning'>
이 문서 섹션의 모든 예제는 데이터베이스 컬럼 이름 별칭을 사용하지 않으며, 컬럼 이름은 TypeScript 키에서 생성됩니다. 

원한다면 컬럼 이름에 데이터베이스 별칭을 사용할 수 있고, `casing` 매개변수를 사용해 Drizzle의 매핑 전략을 정의할 수도 있습니다. 

이에 대해서는 [here](/docs/sql-schema-declaration#shape-your-data-schema)에서 더 자세히 읽을 수 있습니다.
</Callout>

### integer
`integer` `int` `int4`  
부호 있는 4바이트 정수입니다.     

`integer autoincrement`가 필요하다면 **[serial.](#serial)**을 참고하세요.

<Section>
```typescript
import { integer, pgTable } from "drizzle-orm/pg-core";

export const table = pgTable('table', {
	int: integer()
});

```

```sql
CREATE TABLE "table" (
	"int" integer
);
```
</Section>

<Section>
```typescript
import { sql } from "drizzle-orm";
import { integer, pgTable } from "drizzle-orm/pg-core";

export const table = pgTable('table', {
	int1: integer().default(10),
	int2: integer().default(sql`'10'::int`)
});

```

```sql
CREATE TABLE "table" (
	"int1" integer DEFAULT 10,
	"int2" integer DEFAULT '10'::int
);
```
</Section>

### bigint

</Section>

### varchar
`character varying(n)` `varchar(n)`  
가변 길이 문자열이며, 최대 **`n`**개의 문자(바이트가 아님)를 저장할 수 있습니다.

### json
`json`  
**[RFC 7159.](https://tools.ietf.org/html/rfc7159)**에 정의된 텍스트형 JSON 데이터입니다.

자세한 내용은 공식 PostgreSQL **[docs.](https://www.postgresql.org/docs/current/datatype-json.html)**를 참고하세요.
<Section>
```typescript
import { sql } from "drizzle-orm";
import { json, pgTable } from "drizzle-orm/pg-core";

const table = pgTable('table', {
	json1: json(),
	json2: json().default({ foo: "bar" }),
	json3: json().default(sql`'{foo: "bar"}'::json`),
});
```

```sql
CREATE TABLE "table" (
	"json1" json,
	"json2" json default '{"foo": "bar"}'::json,
	"json3" json default '{"foo": "bar"}'::json
);
```
</Section>
  
json 객체 추론을 위해 `.$type<..>()`를 지정할 수 있지만, 런타임 값은 검사하지 **않습니다**. 
이 기능은 기본값, insert, select 스키마에 대해 컴파일 타임 보호를 제공합니다.
```typescript
// will be inferred as { foo: string }
json: json().$type<{ foo: string }>();

// will be inferred as string[]
json: json().$type<string[]>();

// won't compile
json: json().$type<string[]>().default({});
```

### timestamp
`timestamp` `timestamptz` `timestamp with time zone` `timestamp without time zone`  
시간대가 있거나 없는 날짜와 시간입니다.

자세한 내용은 공식 PostgreSQL **[docs.](https://www.postgresql.org/docs/current/datatype-datetime.html)**를 참고하세요.
<Section>
```typescript
import { sql } from "drizzle-orm";
import { timestamp, pgTable } from "drizzle-orm/pg-core";

const table = pgTable('table', {
  timestamp1: timestamp(),
	timestamp2: timestamp({ precision: 6, withTimezone: true }),
	timestamp3: timestamp().defaultNow(),
	timestamp4: timestamp().default(sql`now()`),
});
```
```sql
CREATE TABLE "table" (
	"timestamp1" timestamp,
	"timestamp2" timestamp (6) with time zone,
	"timestamp3" timestamp default now(),
	"timestamp4" timestamp default now()
);
```
</Section>

`date` 또는 `string` 추론 모드를 지정할 수 있습니다.
```typescript
// will infer as date
timestamp: timestamp({ mode: "date" }),

// will infer as string
timestamp: timestamp({ mode: "string" }),
```

> `string` 모드는 어떤 매핑도 수행하지 않습니다. 이 모드는 개발자가 필요에 따라 날짜와 날짜 매핑을 직접 처리할 수 있도록 Drizzle ORM에 추가되었습니다.
Drizzle은 원시 날짜를 문자열로 데이터베이스 `to` 및 `from`에 전달하므로, 동작은 가능한 한 예측 가능하고
데이터베이스 동작과 100% 일치해야 합니다.

> `date` 모드는 날짜를 다루는 일반적인 방법입니다. Drizzle이 데이터베이스와 JS Date 객체 사이의 모든 매핑을 처리합니다.

<Callout type='info' emoji='ℹ️'>
 `timestamp`와 `timestamp with timezone`의 매핑이 동작하는 방식:

 PostgreSQL 문서에 따르면:
 > timestamp without time zone으로 결정된 리터럴에서 PostgreSQL은 시간대 표기를 조용히 무시합니다. 
 > 즉, 결과 값은 입력 값의 날짜/시간 필드에서 파생되며 시간대에 맞춰 조정되지 않습니다.
 >
 > timestamp with time zone의 경우 내부에 저장되는 값은 항상 UTC(Universal Coordinated Time, 전통적으로 Greenwich Mean Time, GMT로 알려짐)입니다. 
 명시적인 시간대가 지정된 입력 값은 해당 시간대에 맞는 오프셋을 사용해 UTC로 변환됩니다. 
 입력 문자열에 시간대가 명시되지 않았다면, 시스템의 TimeZone 매개변수가 가리키는 시간대라고 가정하고,
 그 시간대의 오프셋을 사용해 UTC로 변환됩니다.

 따라서 `timestamp with timezone`의 경우 Postgres 인스턴스에 설정된 시간대로 변환된 문자열을 돌려받게 됩니다. 
 다음 sql 쿼리로 시간대를 확인할 수 있습니다: 
 
 ```sql 
 show timezone;
 ```


</Callout>

`date` 또는 `string` 추론 모드를 지정할 수 있습니다.
```typescript

// will infer as string
date: date({ mode: "string" }),
```

### point
`point`  
기하학적 점 타입입니다.

자세한 내용은 공식 PostgreSQL **[docs.](https://www.postgresql.org/docs/current/datatype-geometric.html#DATATYPE-GEOMETRIC-POINTS)**를 참고하세요. 

타입 `point`는 데이터베이스에서의 매핑을 위해 `tuple`과 `xy` 두 가지 모드를 제공합니다.

<Section>
```typescript
const items = pgTable('items', {
 point: point(),
 pointObj: point({ mode: 'xy' }),
});
```

```sql
CREATE TABLE "items" (
	"point" point,
	"pointObj" point
```

### 데이터 유형 사용자 지정
모든 컬럼 빌더에는 컬럼의 데이터 타입을 사용자 지정할 수 있는 `.$type()` 메서드가 있습니다. 

예를 들어 알 수 없는 타입이나 브랜드 타입과 함께 사용할 때 유용합니다.
```ts
type UserId = number & { __brand: 'user_id' };
type Data = {
	foo: string;
	bar: number;
};

const users = pgTable('users', {
  id: serial().$type<UserId>().primaryKey(),
  jsonField: json().$type<Data>(),
});
```

### Identity 컬럼

<Callout type="info">
이 기능을 사용하려면 `drizzle-orm@0.32.0` 이상과 `drizzle-kit@0.23.0` 이상이 필요합니다.
</Callout>

PostgreSQL은 컬럼에 대해 고유한 정수 값을 자동으로 생성하는 방법으로 identity 컬럼을 지원합니다. 이 값들은 시퀀스를 사용해 생성되며 GENERATED AS IDENTITY 절을 사용해 정의할 수 있습니다.

**Identity 컬럼의 유형**
- `GENERATED ALWAYS AS IDENTITY`: 데이터베이스가 항상 해당 컬럼의 값을 생성합니다. OVERRIDING SYSTEM VALUE 절을 사용하지 않는 한, 이 컬럼에 대한 수동 삽입이나 업데이트는 허용되지 않습니다.
- `GENERATED BY DEFAULT AS IDENTITY`: 데이터베이스가 기본적으로 값을 생성하지만 수동 값도 삽입하거나 업데이트할 수 있습니다. 수동 값이 제공되면 시스템 생성 값 대신 그 값이 사용됩니다.

**주요 기능**
- 자동 값 생성: 시퀀스를 활용해 새 행마다 고유한 값을 생성합니다.
- 사용자 지정 가능한 시퀀스 옵션: 시작 값, 증가 값, 기타 시퀀스 옵션을 정의할 수 있습니다.
- 여러 Identity 컬럼 지원: PostgreSQL은 테이블당 하나 이상의 identity 컬럼을 허용합니다.

**제한 사항**
- 수동 삽입 제한: GENERATED ALWAYS AS IDENTITY로 정의된 컬럼은 OVERRIDING SYSTEM VALUE 절이 없으면 수동 삽입이나 업데이트가 제한됩니다.
- 시퀀스 제약: identity 컬럼은 시퀀스에 의존하므로 충돌이나 누락을 피하려면 올바르게 관리해야 합니다.

**사용 예시**
```ts
import { pgTable, integer, text } from 'drizzle-orm/pg-core' 

export const ingredients = pgTable("ingredients", {
  id: integer().primaryKey().generatedAlwaysAsIdentity({ startWith: 1000 }),
  name: text().notNull(),
  description: text(),
});
```

`.generatedAlwaysAsIdentity()` 함수 안에서 시퀀스에 사용할 수 있는 모든 속성을 지정할 수 있습니다. 또한 이 시퀀스들에 대한 사용자 지정 이름도 지정할 수 있습니다.

PostgreSQL 문서 [reference](https://www.postgresql.org/docs/current/sql-createtable.html#SQL-CREATETABLE-PARMS-GENERATED-IDENTITY).

### 기본값
`DEFAULT` 절은 `INSERT`를 수행할 때 사용자가 명시적으로 값을 제공하지 않은 경우, 해당 컬럼에 사용할 기본값을 지정합니다.
컬럼 정의에 명시적인 `DEFAULT` 절이 붙어 있지 않다면,
그 컬럼의 기본값은 `NULL`입니다.

명시적인 `DEFAULT` 절은 기본값으로 `NULL`,
문자열 상수, blob 상수, 부호 있는 숫자, 혹은 괄호로 둘러싼 상수 표현식을 지정할 수 있습니다.

<Section>
```typescript
import { sql } from "drizzle-orm";
import { integer, pgTable, uuid } from "drizzle-orm/pg-core";

const table = pgTable('table', {
	integer1: integer().default(42),
	integer2: integer().default(sql`'42'::integer`),
	uuid1: uuid().defaultRandom(),
	uuid2: uuid().default(sql`gen_random_uuid()`),
});
```

```sql
CREATE TABLE "table" (
	"integer1" integer DEFAULT 42,
	"integer2" integer DEFAULT '42'::integer,
	"uuid1" uuid DEFAULT gen_random_uuid(),
	"uuid2" uuid DEFAULT gen_random_uuid()
);
```
</Section>

같은 함수의 다른 별칭인 `$default()` 또는 `$defaultFn()`을 사용하면, 
런타임에 기본값을 생성하고 모든 insert 쿼리에서 이 값을 사용할 수 있습니다. 

이 함수들은 `uuid`, `cuid`, `cuid2` 등 다양한 구현을 활용하는 데 도움이 됩니다.

<Callout type="info" emoji="ℹ️">
	참고: 이 값은 `drizzle-kit` 동작에 영향을 주지 않으며, `drizzle-orm` 런타임에서만 사용됩니다.
</Callout>

```ts
import { text, pgTable } from "drizzle-orm/pg-core";
import { createId } from '@paralleldrive/cuid2';

const table = pgTable('table', {
	id: text().$defaultFn(() => createId()),
});
```

같은 함수의 다른 별칭인 `$onUpdate()` 또는 `$onUpdateFn()`을 사용하면, 
런타임에 기본값을 생성하고 모든 update 쿼리에서 이 값을 사용할 수 있습니다. 

컬럼에 동적인 업데이트 값을 추가합니다. 행이 업데이트되면 함수가 호출되며, 
값이 따로 제공되지 않은 경우 반환값이 컬럼 값으로 사용됩니다.
기본값(또는 `$defaultFn`)이 제공되지 않았다면 함수는
행이 삽입될 때에도 호출되고, 반환된 값이 컬럼 값으로 사용됩니다.

<Callout type="info" emoji="ℹ️">
	참고: 이 값은 `drizzle-kit` 동작에 영향을 주지 않으며, `drizzle-orm` 런타임에서만 사용됩니다.
</Callout>

```ts
import { integer, timestamp, text, pgTable } from "drizzle-orm/pg-core";

const table = pgTable('table', {
	updateCounter: integer().default(sql`1`).$onUpdateFn((): SQL => sql`${table.update_counter} + 1`),
	updatedAt: timestamp({ mode: 'date', precision: 3 }).$onUpdate(() => new Date()),
    	alwaysNull: text().$type<string | null>().$onUpdate(() => null),
});
```


### null 아님
`NOT NULL` 제약 조건은 해당 컬럼에 `NULL` 값이 들어갈 수 없음을 의미합니다.

<Section>
```typescript
import { integer, pgTable } from "drizzle-orm/pg-core";

const table = pgTable('table', {
	integer: integer().notNull(),
});
```

```sql
CREATE TABLE "table" (
	"integer" integer NOT NULL
);
```
</Section>


### 기본 키
기본 키 제약 조건은 하나의 컬럼 또는 컬럼 그룹이 테이블의 행을 고유하게 식별하는 데 사용될 수 있음을 나타냅니다. 
즉, 값이 고유해야 하고 null이 아니어야 합니다.
<Section>
```typescript
import { serial, pgTable } from "drizzle-orm/pg-core";

const table = pgTable('table', {
	id: serial().primaryKey(),
});
```

```sql
CREATE TABLE "table" (
	"id" serial PRIMARY KEY NOT NULL
);
```
</Section>
